# Dead Earth MCP gateway и локальный режиссёр

Python 3.12 / Windows amd64. MCP SDK закреплён с хешами.
Gateway и режиссёр используют один ограниченный серверный мост.
Режим D1 preview создаёт и проверяет предложения. В 3.2.0 режим `--mode live` выбирает и запускает ограниченные интерактивные сценарии; физическое исполнение и бюджеты остаются на сервере. Каталог и механики описаны в [документации](../docs/DEAD-EARTH-CINEMATIC.md).

## Подготовка

Из этой папки:
~~~powershell
./setup.ps1 -PythonPath 'C:/Path/To/Python312/python.exe'
~~~

Для модели нужен Docker. На текущем ПК Docker Engine установлен в Ubuntu 24.04 WSL 2.
Docker Desktop не требуется. Официальная инструкция:
https://docs.docker.com/engine/install/ubuntu/

~~~powershell
./model.ps1 -Action pull
./model.ps1 -Action status
~~~

Первый pull скачивает закреплённые веса; последующие используют кеш.
Образ и модель закреплены в models.lock.json, compose и director.example.toml.
Контейнер слушает только 127.0.0.1:11434, ограничен четырьмя CPU и 6 GiB RAM.
GPU не передаётся; запросы дополнительно содержат num_gpu=0.
Один запрос одновременно, контекст 4096, ответ до 160 токенов, общий таймаут 90 с.
После ответа модель выгружается. Облачный API не используется.

В WSL команда start/pull запускает скрытый процесс, который удерживает сервис
доступным между обращениями Windows. Stop останавливает наш контейнер и только
собственный процесс удержания с проверкой PID/времени запуска. Другие дистрибутивы
и контейнеры не останавливаются. Журналы и сведения процесса находятся в runtime/.
Остановка:
~~~powershell
./model.ps1 -Action stop
~~~

## Сервер и режиссёр

В отдельном мире установи наш мод соответствующей версии и включи
[director].enabled=true в config/dead-earth-server.toml.
По умолчанию D1 выключен. Игрок должен быть онлайн; часы работают по активной кампании.
Текущая политика допускает только наблюдение, без расходов бюджета боевой операции.
Полная и свежая зона выбирается по ценности; иначе наблюдается кампания целиком.
Неполная зона не выдаётся за беззащитную.

Оператор запускает /deadearth bridge start. Появляется путь к dead_earth_bridge.json.
Этот файл содержит секрет: его не пересылают и не вставляют в чат.

Один цикл:
~~~powershell
./.venv/Scripts/python.exe -m dead_earth_director.host --bridge '<мир>/dead_earth_bridge.json' --once
~~~

Без --once цикл опрашивает сервер раз в 30 с. Новую цель сервер выдаёт по умолчанию
раз в 18000 активных тиков (15 минут), цель действительна 2400 тиков (2 минуты).
При изменении настроек срок цели ограничивается интервалом решений.
Остальные серверные настройки: director.maximumZoneAgeTicks=1200.
Частота опроса и модель задаются в director.example.toml; свой конфиг можно
передать через --config. Журнал можно задать через --journal.

Результаты пишутся в runtime/decisions.sqlite3. Один goal_id сохраняет выбор и
request_id; повтор после сбоя использует прежний выбор. Уже записанное решение
не вызывает повторную генерацию. Неизвестная схема SQLite не сбрасывается.
Предел — 4096 решений. После смены эпохи сервера или токена host запускают заново;
новый дескриптор не подхватывается молча.

При отказе модели используется проверенный вариант. Изменённая ревизия модели,
лишние JSON-поля, дубли ключей, координаты, численность и неизвестные варианты
не принимаются. Сервер повторно проверяет цель, срок, политику и наличие игроков.
Текст сохраняется как черновик: в игровой чат он не публикуется.

## MCP как операторский пульт

MCP host запускает:
~~~text
command: <director>/.venv/Scripts/python.exe
args: -m dead_earth_director --bridge <мир>/dead_earth_bridge.json
cwd: <director>
~~~

Девять ограниченных инструментов: прежние get_snapshot, get_history, list_catalog,
preview_scenario, propose_scenario, get_scenario_status, cancel_scenario,
а также get_director_brief и preview_director.
Новые два инструмента не исполняют предложение в мире.
Прежний сигнал и радиокаталог доступны отдельно через ручные инструменты;
самостоятельный D1 host их не запускает.

Сырые аргументы проверяются до преобразования SDK. Нет произвольной консоли,
доступа к файлам сервера или универсального спавна. Мир и токен не передаются модели.

## Проверки

Из director:
~~~powershell
./.venv/Scripts/python.exe -m unittest discover -s tests -v
~~~

Реальная проверка модели: tests/integration_world.py вместе с отдельным обычным
сервером (deadEarthDirectorSmoke и deadEarthServerDirectory). Она проверяет ответ модели, отказ контейнера,
сохранённый повтор и скорость активных тиков. Требуется специально подготовленный
отдельный мир; инструмент не предназначен для пользовательского сервера.

[Архитектура](../docs/DEAD-EARTH-DIRECTOR.md).
