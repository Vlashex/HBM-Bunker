# Дообучение и два режима ИИ — 18.10.2026

Первый настоящий QLoRA-эксперимент завершён, но **адаптер отклонён**:
согласие с отложенными синтетическими целями упало с71/160 (44.375%)
до45/160 (28.125%). Рабочий pin Ollama не менялся. Эти проценты не измеряют
успех против живых игроков. Следующая итерация требует улучшения данных и
валидации, а не подбора параметров по уже просмотренному test split.

## Что проверено

| Проверка | База | После обучения |
| --- | ---: | ---: |
| Выбор на160 test, constrained logit choice | 71/160 | 45/160 |
| Полная greedy-генерация, строгий JSON | 8/8 | 8/8 |
| Повтор отброшенной атаки в57 соответствующих случаях | 0/57 | 0/57 |

Полная генерация проверена только на8 примерах;160 выборов через logits
не равны160 проверкам JSON. Валидация32 примеров на шагах16/32/48 дала
37.5% /34.375% /40.625%. Низкая train loss сама по себе не подтверждает качество.
GGUF/CPU-экспорт отклонённого кандидата не выполнялся.

До основного запуска обнаружены и исправлены возврат BatchEncoding в новом
Transformers и переполнение FP16 при initial loss scale128. Первый probe
остановился до optimizer update; второй с scale1 сделал настоящий update.
Это отдельные диагностические запуски, не дополнительные успешные обучения.

## Двойной CPU-режим и память

[Настройка и ограничения](../../docs/DEAD-EARTH-COUNCIL.md).
[Реальный вызов нового council-кода](cpu-council.json) завершил три этапа
за84.828сек. Предложение2 → критик1 → итоговый пересмотр0; все ответы валидны.
Это один синтетический пример, он не доказывает преимущество двух моделей.

Один контейнер6GiB/4CPU; модели4B и2B загружаются поочерёдно, контекст4096,
GPU выключен, keep_alive0. Пик cgroup working set
`memory.current - inactive_file` **5.51GiB**, включая активные файловые страницы;
это не только anonymous RSS весов. Более ранний ручной probe имел3.56GiB:
другой запуск/состояние кеша, его число не заменяет текущий пик.

На ПК31.84GiB. Расчётный игровой бюджет OS7 + клиент8 + сервер7 + ИИ6
даёт28GiB и около3.8GiB запаса. Это оценка с учётом native JVM сверх heap6,
а не измерение шести игроков/большой базы. Новый одновременный стресс клиента,
сервера и двух моделей не проводился. Старый игровой нагрузочный отчёт
относится к5.2.0 и одной CPU-модели. Обучение не входит в игровой бюджет.

У WSL сейчас верхняя граница31GB без swap; она не является резервированием,
но допускает вытеснение Windows при других нагрузках. Конфигурация WSL
не менялась. Для игры рекомендуется отдельный предел10–12GiB после обучения.
