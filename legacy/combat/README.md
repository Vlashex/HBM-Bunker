# Native siege and global mob perception

Epic Siege13.169 remains the selective AI implementation. `legacy/combat/esm-profiles.json` is the canonical default-plus-overrides source; `tools/legacy_siege.py build` expands complete native `esm/entity_ai.json` profiles because this pinned ESM does not inherit missing individual fields. `tools/legacy_siege.py check` rejects stale generated output. Forty profiles enable zombie/husk, thirteen same-species retaliating animal types and twenty-five selected ground SRP forms. Other entities keep native combat/navigation AI. Passive animals never acquire a player before being attacked: native HurtByTarget recruits their own species and ESM melee supplies retaliation damage.

Global sight is separate from that selective AI scope. The user's explicit current setting is `dead-earth/siege.json` mode=`xray`, sightRadius=64 (configurable1..128). A narrow EntityLivingBase.canEntityBeSeen hook lets every logical-server EntityLiving see survival players through any intervening block. It checks the same world, loaded endpoints, living observer/target, spectator exclusion and the configured creative-player policy. The xray branch performs no raytracing, chunk loading or terrain mutation. A LOWEST native EntityJoinWorld listener increases FOLLOW_RANGE to at least the configured range, including ESM-blacklisted mobs. It does not assign targets, create attack goals, override native species/player visibility predicates, or force passive animals to attack. Native special aggro conditions and hardcoded radii of particular vanilla goals remain their own rules.

The pinned SRP entity classfiles declare no canEntityBeSeen/func_70685_l overrides, so every SRP form inherits the common sight hook. SRP EntityAINearestAttackableTargetStatus searches actual World.playerEntities and uses FOLLOW_RANGE plus native suitability/senses. The isolated combat probe temporarily registers an ordinary survival EntityPlayerMP in that native list rather than injecting a parasite's target. It restores the full probe's previous placeholder afterwards.

Optional mode=`glass` retains bounded transparent sight only for configured diggers: native positive LOS remains, while a collision-aware loaded-only supercover ray may cross the configured glass/panes. Its default bounds are128cells,16transparentcells,64rays/server-tick and4targets/entity; native ESM caches plus a per-tick cache remain. Mode=`native` restores native vision. ESM's wrong Xray Distance target lookup is corrected to the observer: otherwise an unregistered player silently yields hardcoded64 instead of the JSON value. ESM's own xray settings remain zero so one explicit DEAD EARTH policy governs vision.

Shared digging settings expand into each complete native profile. Digging is false by default; selected ground forms opt in. The inverted block list admits ordinary terrain, glass, doors and the nine finite-HP defenses, while excluding HBM, containers, machinery, obsidian and bedrock. Pillaring, demolition, teleportation, universal proactive animal aggression and independent ESM boss scaling stay disabled. ESM exact-class modifiers preserve custom SRP melee/target tasks and custom navigators. A canHarvest guard rechecks cached replacements, loaded chunks, Forge mobGriefing and the three-hour bunker grace. Existing World guards still enforce finite V1/V2/V3HP and suppress hostile harvest-after-failed-destroy duplication.

The final isolated SiegeProbe.Session uses real spawned mobs and ordinary server ticks: all-mob xray checks across an opaque HBM wall at40blocks (skeleton, bat, buglin, cow), native follow-range, creative exclusion and no loading at an unavailable target; neutral cows -> actual player hit -> same-species group reaction -> physical retaliation; a parasite starting without target -> natural acquisition through a sealed opaque dirt wall -> native ESM chosen/progressed digging -> physical crossing -> actual player HP loss; and assimilated/primitive/adapted pursuit and attacks. It also checks cached dirt-to-container/HBM replacement, mobGriefing, grace and V3HP. Only the separately labeled terminal-defense assertion forces completion; acquisition/chase/opaque breach never inject a target or dig progress. The combat-only report and the full integrated report remain separate evidence; a narrow pass does not stand in for client, bridge, or whole-pack verification.


`NativeSiegePermissions` calls Forge2860 server APIs directly: mobGriefing, LivingDestroyBlockEvent and virtual Block.canEntityDestroy. Reflectively enumerating ForgeEventFactory also resolves unrelated client tooltip signatures and crashes a dedicated server without ITooltipFlag. The native regression requires that client class to be absent, observes real ESM admission through Forge DENY, verifies cancelled destruction events and preserves a block subclass protection override.

The combat fixture uses an ordinary disconnected EntityPlayerMP with the native NetHandlerPlayServer. Forge FakePlayer always reports damage invulnerability even after capabilities.disableDamage is cleared; it cannot demonstrate physical melee damage. Only the new isolated player's initial join shielding is cleared. Likewise, spawn-animals=false makes native WorldServer kill manually spawned animals on their first update. The session temporarily permits those animals while setting doMobSpawning=false, then restores both settings. It never substitutes a custom retaliation AI, calls AI ticks manually, assigns combat targets, or subtracts HP to manufacture a result. Bounded diagnostics record actual task priorities/mutexes/execution, targets/revenge, positions, entity ticks and committed damage. The group assertion requires the previously unhit responder to approach and damage the player; knockback of the originally struck cow is not counted as pursuit.
