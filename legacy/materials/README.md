# Канонические игровые ресурсы

`catalog.json` — единый источник для точного материала **и формы**. Генерация:

```powershell
python tools/legacy_full_recipes.py --write
```

Генератор выпускает `config/dead-earth/materials.json`, рецепты `dead_earth_materials.zs`,
канонические значения EMC и одинаковые цены старых/новых форм для зон.
У формы есть одна цена `value`; флаг `allowEmc` разрешает её использование в ProjectE.
Цена не копируется в несколько исходных JSON: `progression/emc.json` хранит остальные виды сырья.
`python tools/legacy_materials.py` проверяет соответствие двух material-артефактов;
общий генератор дополнительно проверяет всю прогрессию.

## Что объединено

| Материал | Канон | Особенности |
|---|---|---|
| Железо, золото | Ванильные слитки/самородки, пыль/пластины HBM | HBM сам использует ванильные слитки |
| Медь, алюминий, свинец | Слитки, пыль и существующие пластины HBM | Aluminum и Aluminium считаются одним материалом |
| Титан, вольфрам, бериллий, кобальт, бор | Реально существующие формы HBM | Отсутствующие формы не создаются |
| Уран, торий, литий | Только существующие сырые формы HBM | Топливо/изотопы остаются отдельными; положительный EMC новым формам не выдаётся |
| Сера, селитра | `hbm:sulfur`, `hbm:niter` | Нормализуются варианты sulfur/sulphur, saltpeter/niter/nitre |
| Сталь | Слиток/пыль/пластина HBM | Никаких новых источников стали, рецептов пластин или EMC |

В закреплённом HBM CE 2.6.1.0 нет обычных слитков олова, серебра и никеля.
Мы не заменяем их другими металлами и не выдумываем HBM ID. Остальные установленные
моды преимущественно используют OreDictionary, а не добавляют собственную металлургию.

Проверенные источники: Ex Nihilo Creatio 0.4.7.2 (`OreRegistry`, `ItemOre`, `SieveRegistry`),
Mystical Agriculture 1.7.5 (`EssenceRecipes`), Cucumber 1.1.3 (`RecipeHelper`),
локальный HBM CE 2.6.1.0. Версии/хеши находятся в `legacy/metadata/full.mods.lock.json`.

## Источники выдачи

- Семь рецептов эссенций MA дают конкретные продукты HBM, сохраняя исходные количества
  6/8/4/2/2/8/5 для меди/алюминия/свинца/титана/вольфрама/серы/селитры.
  Удаляется только соответствующий рецепт MA по имени; рецепты металлургии HBM сохраняются.
- Нативные выходы печи и полной таблицы ExN-сит нормализуются после регистрации.
  Поздний native default-provider повторяет нормализацию после перезагрузки ExN-рецептов.
- Блоковые/мобовые drops и подбор предметов проходят ту же конверсию.
- Старые обычные слитки/пыль в инвентаре игрока постепенно приводятся к канону:
  по 9 слотов каждые 20 тиков. Инвентарь помечается dirty, изменения синхронизируются.
  Параметры ограничены конфигом; полный обход чанков/сундуков/МЭ отсутствует.
- JEI скрывает 4 гарантированно существующие запасные формы ExN для железа и золота.
  Металлические ExN-формы, зависящие от ранней регистрации HBM в OreDictionary,
  остаются optional: их отсутствие не порождает невалидных JEI-ссылок. Доступность старых registry entries сохраняется.

## Сохранения и ограничения

Ни один registry entry не удалён. Сундуки, МЭ-ячейки и блоки в сохранённых мирах
не переписываются. Старые формы учитываются по канонической цене и конвертируются
при попадании к игроку. Стаки с любым пользовательским NBT, непустыми ForgeCaps
или количеством, не помещающимся в целевой стак, остаются в исходном виде.
Энергия, зачарования, собственные имена и содержимое контейнеров не теряются.

ExN `item_ore_*:0` — кусочек, `:1` — кусок руды; это промежуточные формы:
4 кусочка → 1 кусок → 1 слиток. Они **не** заменяются 1:1 рудным блоком HBM.
Пыль `:2` и слиток `:3` — равноценные формы для конверсии. Маленькая пыль,
изотопы/топливо, кремниевый слиток HBM и кремний AE2, certus и кварц
остаются отдельными. Разные предметы самого HBM автоматически не схлопываются,
даже если их OreDictionary-группы пересекаются.

Нативные функциональные проверки находятся в `legacyprobe/materials/MaterialsProbe.java`;
они выполняются в общем финальном прогоне, а не при запуске генератора.


### Нативная регистрация культур MA

В закреплённой Mystical Agriculture 1.7.5 `ModChecker` проверяет OreDictionary
при ранней инициализации и не содержит HBM среди распознаваемых модов. Поэтому
семь металлургических/минеральных культур могут остаться soft-disabled: модель
`*_essence.json` в JAR сама по себе не доказывает регистрацию предмета.
Генератор создаёт `mysticalagriculture.cfg` с нативной опцией `seeds=2` ровно для
меди, алюминия, свинца, титана, вольфрама, серы и селитры. Это существующие
`CropType` данной версии; новые registry entries или вымышленные аналоги не вводятся.
Сталь не включается. Поле `crop.seedEnable: 2` хранится в общем каталоге.

Нативная проверка дополнительно сверяет реальные `CropType.getCrop/getSeed/getPlant`,
сопоставляет настоящий верстак с рецептом, проверяет HBM-выход и его количество,
а также собирает нативные drops зрелой культуры. Одной проверки модели/имени
ресурса теперь недостаточно для подтверждения работоспособности фермы.

Первый общий native запуск выявил также отсутствие ExN item_ore_copper/aluminium/lead
в текущем порядке регистрации. Их legacy aliases остаются только условными связями,
проверяемыми по реальному registry. Нативный отчёт явно выводит отсутствующие optional
aliases; обязательная конверсия проверяется на реально зарегистрированных iron/gold.
