# DEAD EARTH SRP 0.2.0 — перенос ядра

Это отдельный срез Minecraft 1.12.2 / Forge 14.23.5.2860: HBM, раннее хранилище,
SRP 1.9.21, Epic Siege 13.169 и координатор 0.2.0. Название профиля намеренно
содержит **Core Port**: архив не является переносом всех модов исходной modern-сборки.
OV, Mutationcraft и SecurityCraft в этом составе отсутствуют.

## Воспроизводимая сборка

Из корня репозитория, Python 3.11+ и JDK 9+ с поддержкой `--release 8`:

```powershell
py -3 tools/legacy_port.py fetch
py -3 tools/legacy_port.py compile --javac "C:\Program Files\Eclipse Adoptium\jdk-17.0.18.8-hotspot\bin\javac.exe" --forge-dir "C:\path\to\isolated-forge-2860-server"
py -3 tools/legacy_port.py build
```

`--forge-dir` должен уже содержать Forge 2860, `minecraft_server.1.12.2.jar` и
`libraries/`. Сборщик не устанавливает Forge и не принимает EULA. `fetch` проверяет
точные размеры и SHA-256 combat lock через `legacy_storage.checked_bytes`; шесть
наследуемых storage pins должны совпадать с отдельным storage lock.

Компиляция вызывает `javac --release 8` с classpath из Forge, Minecraft server и
всех JAR в `libraries/`. Точный вызов и response file находятся в
`work/legacy-coordinator/`. `--tests` дополнительно компилирует `src/test/java` в
`test-classes/`; выполнение тестов остаётся отдельным явным действием. Ничего из
test-classes и compile-only заглушок Minecraft в мод не включается.

Сборщик создаёт детерминированный `mod.jar`, включает `src/main/resources/` вместе
с assets и записывает `FMLCorePlugin=dev.deadearth.legacy.core.LegacyCore` и
`FMLCorePluginContainsFMLMod=true`. Перед упаковкой он повторно сверяет хеш текущих
исходников/ресурсов/заглушек и хеш JAR; после изменения Java требуется новая компиляция.

Результаты в игнорируемом `dist/`:

- `DEAD-EARTH-SRP-0.2.0-Prism.zip` — импортируемый профиль Prism, Java 8, 4 GiB.
- `DEAD-EARTH-SRP-0.2.0-Server-Overlay.zip` — моды, конфиги, Python director/admin,
  скрипты запуска; Forge и Java в архив не входят.

Оба архива сохраняют конфиги и рецепты раннего хранилища. Новый рецепт реле зоны
использует одну железную пластину HBM, красную пыль, две доски и булыжник; энергия,
алмазы и Nether для него не нужны.

## Отдельный сервер

1. Создайте **новую реальную папку** для этого core port, без junction на действующий
   сервер. Установите в неё Forge `1.12.2-14.23.5.2860` штатным installer. Распакуйте
   Server Overlay в эту же папку. Не распаковывайте его поверх действующего сервера.
2. Установите Python 3.11+ с Windows `py` launcher и Java 8. При необходимости
   задайте `DEAD_EARTH_JAVA8` полным путём к `java.exe` или каталогу JRE. Launcher
   проверяет фактическую версию; также ищет Java в `JAVA_HOME` и Java-каталогах Prism.
   Java 17 используется только как компилятор, сервер запускается на Java 8.
3. Самостоятельно прочитайте [Minecraft EULA](https://aka.ms/MinecraftEULA) и создайте
   `eula.txt` с `eula=true`, если принимаете условия. Launcher не записывает согласие.
4. Скопируйте `server.properties.example` в `server.properties`. Сохраните
   `server-ip=127.0.0.1`, проверьте свободный `server-port` и `level-name=world`.
   Мир должен находиться внутри этой папки. Для отдельной консоли человека вручную
   задайте `enable-rcon=true`, свободный `rcon.port`, непустой личный `rcon.password`
   и `broadcast-rcon-to-ops=false`. Пароль остаётся только в локальном properties.
   Все ключи, а также значения `server-ip`, `server-port`, `level-name`, `enable-rcon`, `rcon.port`,
   `rcon.password`, `online-mode`, `white-list`, `enforce-whitelist` пишите без Java
   escape-последовательностей и обратной косой черты. Переносы логических строк
   запрещены для всех настроек. Записанные Minecraft escape-последовательности в
   остальных значениях, например `minecraft\:bedrock` в `generator-settings` или
   `\n` в `motd`, допустимы: launcher не интерпретирует эти настройки.
5. Заранее запустите выбранный локальный Ollama backend и подготовьте модель,
   указанную в `director/director.example.toml`. Этот launcher не запускает Docker,
   не меняет его настройки и не скачивает модели. Host и admin используют Python
   standard library; MCP gateway при отдельном использовании имеет свои зависимости.
6. Запустите `START-SERVER.bat`. После готовности мира и нового bridge descriptor
   supervisor запускает director с `--mode live --bridge world/dead_earth_bridge.json`
   и админку на `http://127.0.0.1:8766`. Токен bridge не выводится в консоль и не
   передаётся в аргументах. Без внешнего ИИ возможен явный запуск
   `START-SERVER.bat --no-ai`; для игрового прогона без обоих Python-сервисов
   добавьте `--no-admin`.

`STOP-SERVER.bat` записывает запрос с UUID именно текущего запуска. Supervisor
закрывает только свои Python children и передаёт `save-all flush`, затем `stop`
через stdin своего Forge child. Он не выполняет `taskkill`, не ищет Java по имени и
не завершает PID из старой квитанции. При долгом сохранении supervisor продолжает
ждать безопасного выхода. Если supervisor аварийно завершился, остановите этот
сервер через его локальную человеческую RCON-консоль; STOP не сигналит чужому PID.

Квитанция и lock: `runtime/legacy-server/`. Логи: `logs/legacy-server-console.log`,
`legacy-director.log`, `legacy-admin.log`. Состояние можно прочитать так:

```powershell
py -3 tools/legacy_server.py status --root "C:\path\to\this-core-port-server"
```

Все действия требуют собственного `legacy-port.json` из Server Overlay и явного
корня сервера. Launcher не переносит миры/профили и не обновляет работающие установки.
Поддержка Java 8, компиляция, игровые проверки и совместимость содержимого должны
подтверждаться общим финальным прогоном; наличие архивов само по себе не подтверждает
прохождение такого прогона.


## Что перенесено в игровую связку

- Нативные фазы SRP 0–10: один контроллер, активное время только при игроках выживания,
  отдельный gain-lock SRP, сохранённые очки/эпоха/квитанции. Действующие существа не
  удаляются при снижении фазы. По умолчанию контролируется только Overworld (`controlledDimensions`).
- Вводный час ease-out от 0.1 до 1; score игроков и предел отклонения, HP/урон и темп
  эволюции — config/dead-earth/coordinator.json. Коэффициенты сезонов SRP: зима1.8,
  жара0.5. В этом срезе климат даёт фазы, погоду и коэффициенты; толстые наледи,
  визуальные пакеты сезонов и terrain/worldgen современного мода ещё не перенесены.
- Собственное реле зоны удерживает 3×3 чанка, максимум шесть неперекрывающихся зон.
  Сканирует только уже загруженные соседние чанки и ограниченное число контейнеров
  за тик; поддерживает IInventory и Forge item capabilities, не раскрывает loot tables.
  Цены ресурсов и ранги известных HBM турелей задаются конфигом. Отдельный AE2 grid
  adapter в данный срез не входит: AE2 ещё не добавлен в его combat lock.
- Один общий стартовый сундук возле спавна: шесть реле, земля, дубовые саженцы;
  выдача не повторяется каждому игроку. CLAIMED сохраняется перед выдачей; при
  аварии в этом месте оператор проверяет сундук, автоматического дубля нет.
- Первые три активных часа защищается область спавна ±16 блоков по X/Z и ±32 по Y.
  SRP/Epic Siege не могут изменять её блоки, игроки могут перестраивать. Это защита
  spawn shelter; генерация самого Outpost Zero бункера и V1/V2/V3 ещё требуют переноса.
- Epic Siege улучшает vanilla zombie/husk: native digging по whitelist обычных
  блоков. ИИ SRP/HBM не подменяется. Независимые hard days/boss-множители выключены.
- 15 событий, 73 зарегистрированных звука, 48 инертных следов, finite queue и
  checkpoint перед эффектом. Пул волны и событие закрыты своим minimumPhase;
  модель не может выбрать координаты, число врагов, команду или неподходящую фазу.
- Сохранённая аналитика урона/смертей; HP учитывается по подтверждённой дельте
  здоровья после обработки брони, spatial attribution относится только к ближайшей
  операции. Выводы об обмане/отвлечении не выдаются за доказанный замысел игроков.
  Окно телеметрии ограничено, полные досье читаются отдельной операцией.
- Админка сохраняет консоль человека, редактор, запуск/отмену событий и кнопки фаз.
  Новые сценарии — JSON графы из существующих звуков/следов/пулов, без Java-пересборки;
  публикация использует scope/revision/staging и нативную повторную валидацию.

MCP: `python -m dead_earth_director --bridge <world>/dead_earth_bridge.json --profile srp`.
Профиль SRP показывает восемь поддерживаемых операций. CPU single/dual council,
ограниченный JSON-выбор и fallback host сохранены; веса не переобучались для этого
переноса. Наличие модов/архива не означает, что локальный Ollama сейчас запущен.
Полный клиент, legacy-версии остальных современных модов и адаптация всей их
прогрессии остаются отдельным этапом; рабочая modern-сборка не заменяется этим ZIP.


## Проверка среза 0.2.0

Финальный прогон: 42 Python-проверки упаковки/запуска, 154 проверки режиссёра/MCP,
2886 утверждений ядра Java8, 17 правил кампании и три DOM-набора админки.
Отдельный настоящий Forge-мир: 170 нативных проверок, 27 проверок моста/админки;
реальный перезапуск того же мира: 46 проверок, включая все шесть билетов чанков.
Длительные таймеры проверены ускоренным активным временем; перезапуск — после
20 обычных тиков сервера. Клиентская GUI-сессия и реальный inference Ollama
в этот прогон не входят. Подробности: verification/srp-core-0.2.0/ в репозитории.
