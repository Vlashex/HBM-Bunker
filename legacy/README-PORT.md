# DEAD EARTH SRP 1.0.0

В готовых архивах этот документ находится в корне как `README-PORT.md`.
Версии и контрольные суммы модов — `full.mods.lock.json`, таблица переноса —
`mod-map.json` рядом с ним. Пути серверных настроек отсчитываются от корня
сервера; в клиентском архиве игровые файлы лежат в `.minecraft/`.

Отдельный форк **Minecraft 1.12.2 / Forge 14.23.5.2860 / Java 8 x64**.
Основа: HBM Community Edition, оригинальные Scape and Run: Parasites 1.9.21,
Epic Siege 13.169 и собственный координатор. OV, Mutationcraft и SecurityCraft
исключены по запросу. Действующие modern-сервер и профили не изменяются.

## Важные настройки

Все пути ниже относятся к папке сервера, `config/dead-earth/`:

- `coordinator.json`: первый час ease-out 0.1→1, три часа защиты спавна, сезон
  144000 активных тиков (2 часа), SRP зимой ×1.8/летом ×0.5, HP/урон/очки,
  зоны, цены ресурсов, ранги турелей, квоты сканирования.
- `climate.json`: слои, рельеф и редкие пики, скорость нарастания/таяния,
  погода, температура, визуальные эффекты и лимиты работы за тик.
- `worldgen.json`: палитра пустоши, кратеры, мёртвые стволы и ограничения записи.
- `defense.json`: урон мобов, задержка между ударами, обычные взрывы и лимит
  повреждённых блоков. Это не защита от ядерного оружия HBM.
- `sieving.json`: компактные сита III/IV/V, соответствие сырья и общая квота
  нативных просеиваний за тик.
- `tools.json`, `machinery.json`, `farming.json`, `progression.json`:
  инструменты, энергия, переработка, грядки и добавочные дропы сит.
- `director/catalog.json`: типизированные JSON-графы событий, звуки, следы,
  пулы волн и лимиты. Новые комбинации не требуют пересборки Java.

Пустошь применяется только к новым чанкам Overworld. Руды ниже дна кратеров,
подземные/подводные структуры, Nether/End и HBM-постройки сохраняются.
Общий радиационный фон и радиоактивная поверхность не создаются. Собственный
лёд тает с сохранением исходных блоков и поставленного игроками обычного льда.
Наледи обрабатывают уже загруженные чанки с квотами; непрогруженная область
догоняет сезон после загрузки, без фоновой генерации мира.

Активное время и эволюция идут при игроках выживания. Реле удерживает 3×3
чанка; максимум шесть неперекрывающихся зон. Оценка включает загруженные
контейнеры и физические AE2-ячейки в приводах/ME-сундуках. Неоткрытые loot tables
игнорируются, содержимое не генерируется ради оценки. Неизвестные/повреждённые
адаптеры не превращаются в нулевую стоимость: зона отмечается неполной.

EMC ограничен явным списком сырья. Готовые технологии, пластины, схемы,
ядерное топливо и биотрофеи исключены. Ресурсные фермы могут приносить прибыль.
Грядка: земля + семя, достаточный свет, воронка/XNet для извлечения; энергия
не нужна. Инструмент лучше повысить до следующего уровня перед зачарованием:
рецепт улучшения не переносит NBT старого инструмента.

## Сита и сжатое сырьё

Обычные сита одного уровня сетки работают вместе в квадрате до 5×5 при клике
в центральное. На каждом должна стоять сетка; для заполнения нужно по одному
сырьевому блоку на сито. Разные скорость/прогресс могут рассинхронизировать группу.

Компактные сита III/IV/V занимают один блок и перерабатывают соответственно
81/729/6561 исходный блок за партию. Тяжёлое сито II — 9; встроенная потеря
двух просеиваний отключена. Рамы следующего уровня создаются из девяти предыдущих.
Сетки III — девять обычных сеток одного материала, IV и V — девять предыдущих.

Сжатие и распаковка обратимы: девять блоков предыдущего уровня ↔ один следующего.
Для III/IV/V нужны соответственно двойное/тройное/четверное сжатие. Добавлены
булыжник, земля, гравий, оба песка, пыль, песок душ, дроблёные камни и шесть видов
листвы. Булыжник сначала дробится в обычной цепочке: рецепт добычи из воздуха
ему не добавляется. Сито использует фактические таблицы Ex Nihilo и HBM.

ПКМ сеткой вставляет сетку, ПКМ сжатым сырьём — вход. Выход можно забирать пустой
рукой или воронкой/XNet; пустая рука с Shift извлекает сетку после партии.
Большая партия выполняется постепенно с общей серверной квотой. Полный выход
останавливает её без повторного броска добычи. При разборке занятое сито выпадает
одним предметом с содержимым и прогрессом; перед улучшением раму нужно опустошить.

## Клиент

- **Prism:** импортировать `DEAD-EARTH-SRP-1.0.0-Prism.zip` как новый экземпляр;
  выбрать Java 8 x64. Начальный лимит памяти 4096 MiB.

  `DEAD-EARTH-SRP-1.0.0-TLauncher.zip`; пошаговая инструкция внутри архива.

  сервера в архивы не входят. Клиент 1.12.2 не подключается к modern-серверу.

## Отдельный сервер и ИИ

1. Создать новую реальную папку без junction на действующий сервер. Установить
   в неё официальный Forge 2860 и распаковать Server Overlay.
2. Установить Java 8 x64 и Python 3.11+ с `py` launcher. При необходимости
   задать `DEAD_EARTH_JAVA8` полным путём к `java.exe`.
3. Прочитать Minecraft EULA (https://aka.ms/MinecraftEULA) и при согласии
   самостоятельно создать `eula.txt` с `eula=true`.
4. Скопировать `server.properties.example` в `server.properties`; проверить
   loopback-адрес и свободные порты. Для личной консоли человека отдельно
   включить RCON с непустым личным паролем. Секреты не передаются модели.
5. Для CPU-ИИ нужен доступный Docker backend с кешем закреплённой Ollama-модели.
   `SETUP-AI.bat` явно загружает первичную модель. `START-SERVER.bat` поднимает
   существующее окружение и проверяет точное имя/digest, без скачивания и
   изменения настроек Docker Desktop. Модель работает на CPU, не на GPU.
6. `START-SERVER.bat`: Forge → новый descriptor → director → админка
   **http://127.0.0.1:8766**. При недоступной модели игровой сервер продолжает
   работать с ограниченным автоматом; это явно отражается в квитанции.
   `--require-ai` требует модель; `--no-ai` отключает host, `--no-admin` — панель.
7. `STOP-SERVER.bat`: запрос текущему supervisor, остановка его Python children,
   `save-all flush` и `stop` через stdin принадлежащего ему Forge-процесса.
   Общий Docker backend не завершается вместе с сервером.

Модель выбирает из разрешённых событий и вариаций, не получает произвольную
консоль, координаты спавна или бюджет волн. Автомат повторно проверяет выбор.
В single загружается только первичная модель, в dual модели вызываются поочерёдно
в CPU-контейнере. Веса сохранены: перенос не выдаётся за новое дообучение.

Квитанция: `runtime/legacy-server/`; журналы: `logs/legacy-*.log`.
MCP при отдельном подключении: `python -m dead_earth_director --bridge
<world>/dead_earth_bridge.json --profile srp` (пакетные зависимости MCP ставятся
в отдельный venv из lock; supervisor host/admin используют стандартную библиотеку).

## Воспроизводимая сборка

```powershell
py -3 tools/legacy_port.py fetch
py -3 tools/legacy_port.py compile --javac "C:\path\to\jdk\bin\javac.exe" --forge-dir "C:\path\to\isolated-forge-2860" --tests
py -3 tools/legacy_port.py build
```

Компилятор JDK 9+ использует `--release 8`; игровой запуск требует Java 8.
Компиляция не запускает проверки. Сборщик сверяет SHA-256/размеры, свежесть
исходников и JAR, детерминированно создаёт три ZIP в `dist/`.
Заглушки Minecraft, probes, тестовые миры, токены и аккаунты не упаковываются.

## Проверка выпуска

Локальная функциональная версия 1.0.0 проверена на полном наборе модов:
47 Python-проверок, 286 записей нативного прогона Forge, bridge/admin27,
47 проверок настоящего перезапуска JVM. Незавершённая партия сита сохраняется
после перезапуска. Отдельно проверены настоящие CPU-модели в single/dual.
Оба игровых клиента загрузились и подключились к новому серверному миру.
Пользовательская визуальная оценка и длительное прохождение остаются ручными.
Нагрузочные замеры не проводились. Протокол: `verification/srp-full-1.0.0/`.

Ограничения native-проверки и модельного примера записаны в протоколе:
один ответ ИИ подтверждает интеграцию, а не улучшение тактики. В журналах Forge
остаются необязательные рецепты Ex Nihilo для отсутствующих Forestry/Thermal;
собственные CraftTweaker-рецепты загружены без ошибок.
Историческое свидетельство core 0.2.0 не заменяет проверки полного состава.
