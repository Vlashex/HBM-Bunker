# Native HBM progression and raw-only EMC

Authoritative sources: recipes.json, sieve.json, emc.json. Generate with `python tools/legacy_full_recipes.py --write`; consistency mode and all tests are deferred until the root final stage. The source does not modify the existing early-storage2ironplate recipe set.

HBM gates: manual sieve2ironplates; automatic sieve/hammer use ironplates+analog circuit7; RFframe uses4ironplates and simple RFcrafter additionally circuit7. AE2inscriber uses steelplates+basic circuit8; native presses13/14/15/19 use steel, certus/diamond/gold/HBMsilicon. MEautomation uses steel/basic8/advanced9 circuits, native cores/processors. Machine recipes consume the normal native ingredients and retain native automation. Non-HBM steel crop recipe names are removed case-insensitively; raw iron/copper/resource plants retain their intended farm profit.

Fourteen high books mirror the modern metal/lapis/diamond/redstone costs: EfficiencyIV-X, FortuneIII-V, UnbreakingIII-V, SilkI. Native StoredEnchantments NBT uses numeric IDs32/35/34/33 and short values. Upgrade ingredients require previous-level NBT using onlyWithTag(); normal vanilla enchantment acquisition is retained. Root owns the native anvil ceiling change.

ExNihiloCreatio0.4.7.2 has JSON registries, but loading a JSON registry replaces all its defaults. We use the native ISieveDefaultRegistryProvider callback registerRecipeDefaults(SieveRegistry), installed in preInit via LegacyProgression.install(config), and native register(ItemStack,StackInfo,float,int). Mesh IDs1string/2flint/3iron/4diamond were inspected. Provider survives defaultreload; generated native config keeps enableJSONLoading=false and flattenSieveRecipes=false. Exact-mesh additive rewards include HBM oreblocks (no fake modern raw-item IDs), sulfur/niter/fluorite, inferium/prosperity metadata0/5 and13vanilla/XLfood crop starts from dirt. Lithium uses actual hbm:ore_gneiss_lithium. No plate/circuit/steel/fuel sieve outputs.

ProjectE1.4.1 EMCMapper.map() has8mapper switches in mapping.cfg. Only CustomEMCMapper is enabled; OreDictionaryMapper, APICustomEMCMapper, CustomConversionMapper (including its bundled defaults/metals), CraftingMapper, FluidMapper, SmeltingMapper and APICustomConversionMapper are disabled. pregenerate=false prevents cache reuse. custom_emc.json contains a finite explicit raw allowlist and explicit zero examples; every unlisted technology, plate, circuit, finished material, isotope/fuel or SRPtrophy has no value. Raw mineral/wood/crop/food outputs retain EMC and intentional native resource-farm profit. A LOWEST EMCRemapEvent listener removes any unlisted third-party additions before ProjectE calls cacheFullKnowledge, so zero/unlearnable remains the default even for API writes.

Root integration: call LegacyProgression.install(config) in preInit and LegacyProgression.postInit() after itemregistration. postInit validates every actual recipe/reward/positive-EMC native item ID. No runtime world calls are made by this subsystem. LegacyProgression.rawOnly()/sieveProviderRuns() support final-stage physical assertions. Native costs/recipes/EMC/JEI must still be exercised in the fresh full pack; source inspection and successful Java compilation are not a full-playthrough claim.

Material canonicalization is defined once in `legacy/materials/catalog.json`; see `legacy/materials/README.md`. The full progression generator incorporates those explicit MA outputs, native-safe aliases, raw EMC values and zone prices. Registry entries and tagged/capability-bearing legacy stacks remain intact.
