# Инструкции для следующих изменений

- Отвечай пользователю по-русски. Рабочий проект находится в этом Git-репозитории.
- Канонические исходники: `pack/patch/`, `pack/config/`, `metadata/mods.lock.json`.
- Java-координатор Dead Earth: `mods/dead-earth/`; собирается отдельно от ZIP MVP.
  Java 21, Gradle `test build` и `runGameTestServer`; руководство в `docs/DEAD-EARTH-FOUNDATION.md`.
  Не превращай сохранённый `RUNNING` в автоматический повтор; новая схема не должна
  молча заменять неизвестную или повреждённую кампанию.
- MCP gateway: `director/`; отдельный Python 3.12 venv, официальный SDK и lock
  с хешами. Проверки: `.venv/Scripts/python.exe -m unittest discover -s tests -v`
  из `director`. Мост остаётся выключенным по умолчанию, только 127.0.0.1.
  Не читай/не печатай runtime-дескриптор в чат; проверяющие программы читают его
  сами и выводят только несекретные результаты. Не добавляй произвольную консоль в MCP/модель.
- Пользователь разрешил непрерывную разработку и локальные релизы. Клиентские и
  серверные проверки накапливай на связный срез, не запускай после каждого коммита.
  Небольшие проверки по изменённой логике остаются; перед выпуском — общий прогон.
- Независимые GameTest-прогоны используют новую `deadEarthGameTestDirectory`:
  SavedData сохраняются между запусками. Предыдущие миры испытаний не очищай автоматически.
- Радиокаталог описан в `docs/DEAD-EARTH-RADIO.md`: выбор только по обнаруженным
  объектам, окончательная физическая проверка без загрузки чанков. Схема сценариев 2
  читает схему 1; при переносе сохраняй UUID/сроки и пределы восстановленной очереди.
  Сырые MCP-аргументы проверяются до SDK, иначе он удаляет неизвестные поля.
- Климат v1 активен: `climate/`, `dead_earth_climate.dat`
  schema2 (читает schema1). Время только Campaign.activeTicks, сохранённая длительность не меняется
  молча: правки серверного конфига применяются со следующей фазы. Маркеры сохраняются до уведомлений; marker текущего прогноза допустим
  только в его временном окне. Полный восьмидневный круг проверяется unit-тестами,
  короткий клиентский прогон не подтверждает 160 минут физических погодных эффектов.
- Сезонные адаптеры `mixin/`, `compat/Season*` сохраняют нативные стадии и конфиги.
  Исходные assets собственного мода должны попадать в Git (исключение assets/ в .gitignore).
  Native full-pack GameTests используют official configureMockConnection для embedded игроков.
- Станции после загрузки проходят VERIFYING без force-load; отсутствие блоков
  переводит их в UNCERTAIN. Отменённая смерть не является фактом наблюдения.
- Не запускай старые генераторы из внешней папки `work/`: они содержат исторические
  пути и могут перезаписать текущие рецепты. Сборщик здесь упаковывает исходники напрямую.
- Не меняй сохранения и другие профили PrismLauncher без запроса пользователя.
- Сохраняй роль HBM в металлургии. Сталь/пластины не должны получать дешёвые обходы.
- EMC распространяется на сырьё; готовые технологии, пластины, схемы, ядерное топливо
  и биотрофеи исключены. Работающие ресурсные фермы и переработка могут приносить
  прибыль EMC: это намеренное облегчение, не ошибка, требующая автоматического запрета.
- Высокие книги имеют рецепты HBM; ванильное получение/объединение тоже разрешено.
- Новые моды должны соответствовать Minecraft 1.21.1 NeoForge. Обновляй lock-файл
  и ограничения EMC при изменении состава; не подменяй версии автоматически.
- Не коммить JAR/ZIP, кеши, миры, аккаунты, токены, полные журналы или настройки пользователя.
- Перед заявлением о готовности: `python -m unittest discover -s tests -v`,
  `python tools/release.py check`, затем проверки по характеру изменения.
- `verification/mvp/` — историческое свидетельство. Оно не подтверждает новые изменения.
- Упаковка: `python tools/release.py build`. Результат в игнорируемой папке `dist/`.
- Обновляй `CHANGELOG.md` и соответствующие документы. Формат выпуска — в CONTRIBUTING.md.
- Не делай push, публичный релиз, изменение remote или перенос профилей без запроса.

- Рабочее расширение интерактивного режиссёра: `director/Cinematic*`,
  `pack/config/dead-earth/director/catalog.json`, `docs/DEAD-EARTH-CINEMATIC.md`.
  Новые события — типизированные конечные графы JSON, никаких команд/eval.
  MCP get_cinematic_brief/choose_cinematic/get_cinematic_queue; host `--mode live`.
  APPLYING сохраняется перед эффектом и не повторяется, даже после reload.
  Одноразовые действия игроков запоминаются на текущем узле; время реакции идёт
  после последнего предвестника. Бюджет повторно считается при допуске.
  Полный игровой прогон включает namespace dead_earth_cinematic; новый мир каждый раз.
  Существующая 3.1.0 всё ещё D1; рабочий срез не считать выпущенным до нового релиза.

- По прямому уточнению пользователя неоткрытые контейнеры с отложенной loot table
  исключаются из стоимости до открытия и не блокируют complete/сценарии.
  Отчёт хранит ignoredLootContainers; сканер не генерирует loot.
  Ошибки адаптеров, неизвестные турели/цены/ячейки и пропущенные чанки не игнорируются.
  Полный GameTest-прогон также включает namespace dead_earth_loot_review.

- Ревизия режиссёра: GameTest namespace dead_earth_cinematic_review входит в общий прогон.
  Сигналы в сохранении — множество (порядок незначим, дубликаты запрещены).
  Нечитаемый director.dat не отключает базовый runtime и не перезаписывается.
  owned_waves сохраняет живые UUID после unload; clear только по подтверждённому исходу.
  mine подтверждается после dispatch, отмены и проверки загруженности/изменения блока.
  Для move направление берётся из key; навигация нативная, нахождение пути не гарантировано.

- Пустошь: `worldgen/`, `config/dead-earth-worldgen.toml`, namespace `dead_earth_worldgen`.
  Сохраняй все HBM структуры и архитектурные features; последнее уточнение пользователя
  отменяет их отключение. Собственный ash инертен; радиацию HBM глобально не отключай.
  Noise overrides изменяют только surface_rule, карта биомов/роутер/руды сохраняются.
  Генератор пишет только текущий новый чанк; существующие блоки не переделывает.
  HBM structure references текущего чанка защищают основание от новых кратеров.
  Точечные vanilla terrestrial exclusions не распространяй на подземные/подводные/Nether/End.
  COMMON worldgen snapshot требует перезапуска. Полный игровой набор включает новый namespace.
  Промежуточные 151 unit/3 GT не заменяют обычный мир/клиент/полный прогон перед выпуском.

- Локальный выпуск 3.2.0 включает live-режиссёра и пустошь:151 unit/74 GT, новый обычный сервер и настоящий Prism join. HBM ground adapters сохраняют нативный placement; NativeGameTests обязательны в полном namespace. Сервер NeoForge этой установки хранит dead-earth-server.toml в config/, не world/serverconfig/. Новые установленные профиль и сервер используются человеком: не заменять их мир/моды во время игры и не останавливать без запроса. Портативный BAT остаётся отдельным срезом; локальный runtime launcher находится вне Git в папке установленного сервера.

- Локальная админка: `director/dead_earth_director/admin*.py`, `admin_web/`,
  `start-admin.bat`, `docs/DEAD-EARTH-ADMIN.md`. Наблюдение и отдельная консоль человека
  по прямому запросу пользователя. HTTP loopback, фиксированные GET/HEAD маршруты и
  POST /api/console/command с Origin/nonce/квитанцией UUID. RCON только при server-ip=127.0.0.1.
  Не добавляй консольные полномочия в MCP/модель. Нельзя автоматически повторять команду
  при uncertain; квитанция сохраняется перед сетевой отправкой, не вытесняется автоматически.
  Пароль RCON остаётся backend-only, журнал/история команд не входят в экспорт ИИ.
  Не опрашивай get_cinematic_brief: чтение может создать цель. Только snapshot/queue.
  decisions.sqlite3 открывается mode=ro; admin.sqlite3 — отдельная ограниченная история.
  Кампания/эпоха обязательны для привязки решений; старые записи без аудита не угадывай.
  gap_before вычисляется до прореживания графика. Архив исходов/наблюдений не зависит
  от короткого кольцевого журнала сервера. Новые assets и BAT должны попадать в упаковку.
  Проверки: Python-набор director и `node director/tests/admin_ui_test.cjs` из корня;
  DOM-проверка не подтверждает внешний вид в браузере. Изменение только админки
  не требует повторного запуска игровых тестов, если Java/моды/конфиги не менялись.

- Общий стартовый запас: `starter/`, `docs/DEAD-EARTH-STARTER.md`, namespace
  `dead_earth_starter` в полном GameTest-наборе. Только один запас на весь мир,
  через OutpostZero hub_starter, независимо от игроков/числа сундуков.
  Не заменяй квитанцию при ошибке чтения и не делай автоматическую повторную выдачу.
  Проверяй вместимость до claim/checkpoint; не очищай существующий лут.
  Загрузка с диска в тесте требует нового DimensionDataStorage: set(name,null)
  создаёт negative cache и не имитирует настоящий перезапуск.
