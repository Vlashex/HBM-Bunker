# Локальный запуск DEAD EARTH

Код проекта находится в `C:\projects\DEAD-EARTH`, с самостоятельной историей Git.
Прежний путь HBM-Bunker-Foundation сохранён как junction для совместимости
существующих настроек. В `C:\projects\Dead-Earth-Server-3.2.0` находится junction
на действующую серверную установку. Это сохраняет ожидаемый BAT относительный
путь; серверные файлы и мир физически остаются в прежнем месте.

На рабочем столе:

- `DEAD EARTH - Start Server` — старт сервера, Docker и ИИ через start-dead-earth.bat.
- `DEAD EARTH - Stop Server` — штатный запрос сохранения мира и остановки через stop-dead-earth.bat.

Ярлыки используют отдельные сгенерированные зелёную и красную иконки с
размерами16–256px. [Исходники и промпты](../launcher-icons/README.md).
Для повторного создания выполни из корня проекта:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File tools/install-server-shortcuts.ps1
```

Создание ярлыков само по себе не запускает и не останавливает сервер.

Дважды нажми start-dead-earth.bat в корне репозитория: запустятся уже настроенный сервер, Docker с CPU-моделью и live-режиссёр. Повторный запуск при работающем экземпляре сообщает его адрес и не создаёт второй сервер.

- start-dead-earth.bat status — состояние без запуска.
- start-dead-earth.bat stop — запросить остановку ИИ и сохранение/остановку мира.
- stop-dead-earth.bat — отдельная точка штатной остановки для ярлыка.

BAT использует существующий локальный supervisor в соседней папке Dead-Earth-Server-3.2.0 и его deployment.json. Название папки осталось от 3.2.0: игровой состав релиза v4 идентичен. Мир, моды и профили не перезаписываются. Это точка запуска для текущего ПК; автоматическая установка на чистом ПК остаётся отдельной задачей.

## Проверка CPU-модели

`deployment.json` поддерживает `model_backend`: `auto`, `wsl`, `windows`.
На текущем ПК установлено `wsl`: веса находятся в Ubuntu, Docker Desktop
используется отдельно для playit. `auto` предпочитает доступный движок с
существующим томом модели; окончательная проверка сверяет имя и SHA256 pin.
Само наличие Windows Docker CLI больше не означает готовность модели.

Запуск использует кеш без автоматического скачивания образа/весов. Если
нужна первоначальная подготовка, выполни `director/model.ps1 -Action pull`
с выбранным `-Backend`. В WSL поднимается установленная служба Docker;
при неисправном systemd запуск завершается с диагностикой, без создания
параллельного Docker Engine. Массовый перезапуск WSL не выполняется автоматически.

При ошибке смотри `logs/model-startup.log` в серверной папке; причина также
попадает в `status.json`. Срок ожидания подготовки модели ограничен 120 секундами.
