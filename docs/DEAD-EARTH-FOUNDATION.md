# Dead Earth Foundation

Первый реализованный срез: собственный мод **Dead Earth Coordinator 0.1.0-dev**
для Minecraft 1.21.1 / NeoForge 21.1.262 / Java 21. Он добавляет часы кампании
и один безопасный сценарий. Климат, WARDEN, MCP и OVERSEER относятся к следующим этапам.

## Поведение

Кампания получает постоянный UUID. Часы увеличиваются один раз за серверный тик,
только когда в списке сервера есть онлайн-игроки. Один активный день — 24 000 тиков;
при 20 TPS это 20 минут. Сон, `/time set` и время, проведённое без игроков,
не прибавляют пропущенные сутки. Скорость реального счёта снижается вместе с TPS.

После загрузки сервера создаётся новая эпоха соединения. Постоянный ID кампании
и уже принятые заявки сохраняются. Новые предложения с чужой эпохой отклоняются;
ранее принятая очередь может продолжить работу после перезапуска.

Единственный шаблон — `warning_beacon_v1`. Через **200 активных тиков** после заявки
он отправляет в чат `[DEAD EARTH] Тестовый сигнал <scenario_id>`.
Окно истекает через 1200 активных тиков от подачи. Если нет игроков или не загружен
чанк точки появления мира (`test_anchor`), эффект ждёт. Чанки принудительно не загружаются.
Блоки, мобы, инвентари, погода и данные HBM этим сценарием не изменяются.

## Команды оператора

Требуется уровень полномочий **2**. В серверной консоли начальный `/` не нужен.

```text
/deadearth status
/deadearth preview 11111111-1111-4111-8111-111111111111
/deadearth submit 11111111-1111-4111-8111-111111111111
/deadearth status <scenario_uuid>
/deadearth cancel <scenario_uuid> <revision>
```

`preview` не создаёт событие. `submit` возвращает ID сценария и ревизию;
повтор того же request UUID возвращает прежнюю квитанцию, включая завершённую,
и не назначает новый срок. Для нового сигнала нужен новый request UUID.
`cancel` работает только до исполнения и требует текущую ревизию, обычно `0`.
Старый номер ревизии или завершённый сценарий дают отказ.

Ответы команд представлены компактным JSON для диагностики. Это локальные
операторские команды, а не уже реализованный сетевой MCP-интерфейс.

## Сохранение и сбои

В папке `data/` самого мира находятся:

- `dead_earth_campaign.dat` — идентификатор, версия схемы и активное время.
- `dead_earth_scenarios.dat` — квитанции, дедлайны и состояния сценариев.

Перед эффектом состояние `RUNNING` записывается с подтверждением дисковой операции;
после эффекта сохраняется `COMPLETED`. Существующие асинхронные записи SavedData
дожидаются завершения, чтобы более старая запись не затёрла checkpoint.
Это редкие небольшие синхронные записи при операторских действиях и сценариях,
а не запись на диск каждый тик.

Сохранённый `RUNNING` после загрузки превращается в `UNCERTAIN` и автоматически
не повторяется. Ошибка записи выключает координатор до перезапуска и оставляет
диагностику в серверном журнале. При неизвестной схеме, чужой кампании или повреждённой
истории мод сохраняет исходные данные и отказывается исполнять события.

Это не транзакция со всеми изменениями игрового мира и не универсальный механизм
отката. В текущем срезе единственный внешний эффект — сообщение в чат.
Для будущих взрывов и других необратимых действий нужны отдельные протоколы исполнения.

История ограничена **1024 квитанциями**. После заполнения новые заявки отклоняются;
старые ID не удаляются автоматически, чтобы их повтор не создал новое событие.
Ротация долговременной истории появится вместе с директором.

## Сборка и проверки

Исходники находятся в `mods/dead-earth/`. В Git нет wrapper JAR и игровых бинарников.
Сначала получить и проверить закреплённый wrapper, затем использовать Java 21:

```powershell
python mods/dead-earth/bootstrap.py
cd mods/dead-earth
./gradlew.bat test build
./gradlew.bat runGameTestServer
```

Результат: `mods/dead-earth/build/libs/dead-earth-0.1.0-dev.jar`.
Java 21 нужно назначить через `JAVA_HOME` или локальные настройки Gradle.
Версии инструментов и checksum Gradle зафиксированы; сторонние Java-зависимости
закреплены в `gradle.lockfile`. GameTest использует отдельную папку `run-gametest/`.

Для проверки полного комплекта модов используется отдельный сервер и отдельная
папка dev-клиента `mods/dead-earth/run/`. Перед запуском туда помещаются ровно
закреплённые внешние моды, существующий балансирующий патч и канонические конфиги.
Сам координатор в dev-клиенте уже предоставляется исходным проектом: второй его JAR
в `run/mods/` добавлять нельзя.

Автоподключение dev-клиента к подготовленному локальному серверу:

```powershell
./gradlew.bat runClient '-PdeadEarthSmokeServer=127.0.0.1:25581'
```

Выпускной ZIP `0.1.0-mvp` пока не включает этот мод. Его рецепты, список 28 внешних
JAR и патч 1.2.0 не менялись; Java-координатор собирается из нового исходного проекта.
Для игрового добавления использовать отдельный профиль и резервную копию мира.

Проверенные результаты и ограничения записаны в
[отчёте Foundation](DEAD-EARTH-VERIFICATION.md). В полном dev-клиенте выявлена
ошибка ProjectE; чистая проверка обычного профиля Prism пока не подтверждена.
