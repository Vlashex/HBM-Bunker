# P03: сериализация снимка локального моста

Периодическое обновление кеша моста раньше собирало DTO, сериализовало весь снимок
через Gson и копировало JSON для ограниченной проекции прямо на серверном потоке.
Обновление происходит раз в 200 тиков, только пока мост включён. Изменение переносит
Gson и подготовку проекции в один daemon worker; сбор фактов остаётся на сервере.
Первый снимок при запуске моста публикуется синхронно, поэтому успешный запуск
по-прежнему сразу предоставляет `get_snapshot`.

## Граница потоков

`CoordinatorRuntime.Snapshot` содержит UUID, строки, числа, enum и неизменяемые
records. `ObservationLog.Snapshot` уже копирует свои списки; конструктор общего
снимка также копирует списки станций и сводок зон. В снимке нет мира, сущностей,
инвентарей, NBT или конфигурационных объектов. Worker получает только этот DTO
в `Optional` и время capture; пустой `Optional` обозначает `enabled: false`.
Статический encoder не захватывает `runtime` или `server`.

В очереди может находиться одна ожидающая работа, кроме уже выполняемой.
Следующий capture заменяет ожидающий предыдущий. Старый кеш доступен читателям,
пока новый JSON не подготовлен целиком. Ошибка кодирования или подготовки
проекции сохраняет прежний кеш, записывается в журнал и не останавливает worker.
Каждая работа завершается результатом: опубликована, вытеснена/закрыта либо ошибка.

Копирование и ограничение JSON выполняются вне lifecycle lock. Короткая критическая
секция связывает проверку закрытия с заменой атомарной ссылки кеша. `close()`
отбрасывает ожидающую работу, завершает её и выполняемую работу как отменённые и
возвращается без ожидания encoder. Поздний результат закрытого worker не
публикуется. Новый запуск создаёт отдельные worker и кеш.

`cache_age_millis` считается от `System.nanoTime()` при серверном capture,
а не от окончания сериализации: ожидание worker и время кодирования входят
в возраст наблюдений. Время кампании для этого не используется.

## Экономия и ограничения

Из серверного тика удалены периодические `Gson.toJsonTree`, глубокая копия JSON
и ограничение массивов для кеша. Частота capture и объём собираемого DTO прежние;
копирование DTO остаётся на серверном потоке. Worker не ускоряет чтение мира,
не меняет политику выбора сценариев и не выполняет эффекты. Подтверждённый барьер
сохранения перед APPLYING/эффектом остаётся синхронным.

Это перенос ограниченной работы с серверного потока, а не подтверждённый прирост
TPS. Мост выключен по умолчанию; при выключенном мосте worker не создаётся.
Численные результаты профилирования сюда добавляются только по фактическому
замеру. Короткие unit-тесты не подтверждают изменение MSPT обычного мира.

## Проверки

`AsyncSnapshotPublisherTest` использует latch и ограниченные ожидания без sleep:

- один daemon encoder и только последний из ожидающих снимков;
- сохранение кеша и дальнейшая работа после ошибки encoder или проекции;
- быстрое закрытие при заблокированном encoder, завершение ожидающих результатов,
  отсутствие поздней публикации и изоляция следующего поколения;
- включение задержки encoder в возраст кеша;
- защита списков DTO от изменения до сериализации.

Существующие `SnapshotCacheTest` сохраняют проверки ограничения проекции,
неизменяемости выданных JSON и возраста независимо от часов кампании. Общие
bridge/GameTest проверки нужны для реального запуска, первого снимка и остановки.
Фактические команды и результаты общего прогона фиксируются в сводном отчёте
проверки, а не предполагаются этим документом.

## Откат

P03 откатывается отдельным коммитом: возвращаются синхронные периодические
сериализация/публикация, прежний DTO и реализация кеша. Форматы сетевого протокола
и сохранённых миров не изменяются; миграция при откате не требуется.
