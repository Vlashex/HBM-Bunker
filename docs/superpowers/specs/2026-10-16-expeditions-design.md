# DEAD EARTH — Expeditions, первый игровой срез

Основание: [roadmap](../../DEAD-EARTH-ROADMAP.md), продолжение Foundation.
Пользователь разрешил непрерывную разработку, коммиты и локальные выпуски;
отдельные согласования этапов не требуются. Публичная публикация не включена.

## Результат

Координатор получает проверенные наблюдения о команде и известных регионах.
Оператор может разместить небольшую заброшенную станцию связи в свободном месте.
При обнаружении станции появляется запись экспедиции. Это первая точка интереса
для будущих событий и MCP, без автономных атак и без изменения пользовательских миров.

## Границы

- Minecraft 1.21.1, NeoForge 21.1.262, Java 21; внешние версии и баланс остаются закреплены.
- Наблюдение раз в 200 активных тиков: только онлайн-игроки, регион 64×64,
  измерение, здоровье; смерти записываются событием. Сундуки и инвентари не сканируются.
- История содержит не более 512 записей, известные регионы — 1024, игроки — 64.
  При достижении лимита регионов новые не добавляются; последние игроки обновляются.
- Сохранение schema=1 связано с UUID кампании. Неизвестные/повреждённые данные
  отключают подсистему и сохраняются без замены, как в Foundation.
- Станция связи: фиксированный небольшой чертёж из ванильных блоков. Только Overworld,
  загруженные чанки, границы мира, полностью свободный объём, не ближе 32 блоков
  к игрокам. Не очищать площадку и не заменять существующие блоки.
- Размещение оператором, preview до изменения. Не более 64 объектов. UUID запроса
  связывается с координатами; дубликат возвращает существующую запись, конфликт отклоняется.
  Сначала сохраняется PLACING; после успеха READY. После сбоя PLACING становится
  UNCERTAIN и автоматически не достраивается.
- Обнаружение READY-объекта игроком в радиусе 12 блоков записывается единожды для
  кампании; не выдаёт EMC, предметы или скрытые технологические открытия.
- Наблюдения и объекты доступны через операторские команды; MCP и локальная модель
  будут отдельным следующим срезом поверх этих данных.
- ProjectE: сначала исследовать ServiceLoader/TCCL; минимальная совместимость
  допустима только при подтверждении причины. Не менять внешний JAR.

## Проверка и выпуск

Небольшие тесты поведения при реализации; общий JUnit/GameTest и полный клиент/сервер
после накопления среза. Воспроизводимость, дубли, повреждённые данные, неподходящая
площадка, обнаружение и перезапуск обязательны. Собственный мод включается в
поставку явно, с закреплённым SHA-256. Релиз локальный; неизменяемый MVP сохраняется.
Не выдавать dev-клиент за проверку Prism; непроверенные ограничения указать в выпуске.
