## Shared API contract
Human-only GET /api/config returns {schema:1,state,nonce,server:{revision,worldEpoch,campaignId,sections:[...]}}. A section is {id,label,fields:[...]}; a field is {key,label,type,value,policy,help,min?,max?,step?,choices?}. Types boolean,integer,number,string,json. Policies hot or restart. Revision is a SHA256 of canonical active configuration. Bounds/help come from Java, never independently invented in JS. Separate unknown/stale/offline states; no default-value fallback presented as live data.

Human-only POST /api/config/apply receives {request_id,world_epoch,revision,mode,changes}; mode hot|restart, changes is {sectionId:{fieldKey:typedValue}} with only edited fields. Existing same-Origin/nonce/size/idempotency protections apply. Runtime parameter paths are whitelisted internally, never supplied by browser. Nonces/console/secret settings are not exposed to models. A timeout after sending is uncertain: do not resend automatically. GET /api/config/receipt?request_id=... retrieves durable human-console receipt and reconciliation where supported.

Java command deadearth config view returns {schema:1,status:ready,revision,worldEpoch,campaignId,sections:[...]}. deadearth config validate <epoch> <revision> <uuid> and deadearth config apply <epoch> <revision> <uuid> read config/dead-earth/config-staging/<uuid>.json. Stage is {schema:1,requestId,worldEpoch,baseRevision,mode,changes}. Native result {schema:1,accepted,state,requestId,revision,errors:[{section,key,code,message}]}; state validated|applied|restart_pending|rejected. Error messages bounded and no stack traces/paths/secrets. Receipt IDs are UUIDs, revisions exact64 lowercase hex, current world epoch required. Duplicate same request must not reapply, conflicting UUID payload rejected. Validation never writes live config. Native apply validates entire batch then persists with rollback/recovery, commits runtime settings together on server thread; malformed/missing/unsupported fields preserve the last good configuration. Pending runtime tasks keep their outputs/rolls/progress; no inventory truncation, mob respawn, phase reset or existing terrain rewrite.

## Configuration scope/policies
Expose own existing game configs coordinator, siege, relay-siege, climate, farming, machinery, defense, tools, sieving, worldgen, progression and SRP phase roster where safe. Prefer restart for structural arrays/maps, slots/capacities, dimensions, tickets/zone geometry, phase thresholds/roster, worldgen/progression/registry-dependent values and any field without a proven safe live adapter. Numeric coefficients/rates/budgets, sight radius, defense damage/cooldowns, farming speed/light/acceleration, machinery rates may be hot with bounded native validation. Timers tied to activeTicks arithmetic (seasonTicks,introTicks,bunkerGraceTicks) are restart-only in this first implementation; retain current saved campaign data. Do not falsely offer unsupported fields as hot. Expose catalog rules using existing validated catalogue mechanism if practical; preserve all events/traces/sounds, current operation graphs. Existing catalogue rules list must not remain an unrelated editable JSON dump; link into config form or provide typed rule editor. No arbitrary third-party config editing.

Hot sight changes affect existing loaded entities in bounded batches and future entities, retain native aggression/creative policies. Avoid force-loading and duplicate event registration. Validate min/max from actual validators (sight1..128). Failures should reject change, not terminate server; do not disable watchdog globally.

## Restart pathway
Do not mount Docker socket or give admin privileged Docker access. Native restart apply writes durable validated config plus runtime/compose/config-restart-request.json marker only after success. Marker schema1 {requestId,worldEpoch,revision}. Minecraft container supervisor detects a validated pending marker, sends save-all flush then stop on private stdin, waits for actual Java exit and starts Java again inside the same container. Preserve shared network namespace and admin/director availability. External SIGTERM overrides restart and stops service. Startup failure after a config restart must restore last-good config backup and attempt previous configuration once; no endless retry loop. Persist queued/stopping/starting/ready/failed state to runtime/compose/config-restart-state.json. UI may poll a dedicated human-only /api/config/restart endpoint; distinguish saved/restarting/applied/failed and never claim running before readiness/epoch acknowledgement. Marker files must be bounded, nonsymlink and request-bound; no arbitrary command/path fields.

Edit fetches fresh schema/values, enables inputs with inline field help and HTML min/max/step. Separate Горячие настройки and Требуют перезапуска with field labels and explanations. Hot apply sends hot edits only and leaves restart edits pending; restart apply submits all pending edits. No extra permission popup required after explicit restart button; show an inline notice that players disconnect and world is saved. New config nav acceptable but integrate/replace existing parameter enumeration. Escape all text with DOM APIs. Keyboard accessible labels/help/status; existing page styling retained.
