# Первое дообучение режиссёра

Пользователь выбрал: выбор тактик по обстановке и истории атак. Тексты/лор
не входят в этот срез. Продолжаем автономно по согласованному режиму разработки.

## Результат и границы

Кандидат LoRA/QLoRA для Qwen3.5-4B, обученный локально в отдельном Docker
контейнере, с отчётом сравнения до/после и воспроизводимым набором данных.
Сначала проба памяти/один шаг; при непригодности4B проверяется меньший кандидат
того же семейства, с явной записью смены базы. Рабочий inference остаётся CPU.
Ни Java, ни мир, ни уровни полномочий MCP не меняются. Ответ — только option
из уже разрешённого сервером списка. Новые веса не заменяют production pin
автоматически. Не утверждать улучшение игрового опыта по одному training loss.

Варианты: prompt-only не меняет веса; полное обучение4B не соответствует
памяти ПК; выбран малый адаптер и проверка на отдельном наборе. GPU RTX2060
SUPER8GiB применяется только для разового обучения/внутреннего сравнения.

## Данные и задача

Runtime context: season, pressure, parasite_phase; options содержит option,
event, title, tactic, faction, weight; recent содержит event/outcome.
Сейчас options не содержит event, что мешает сопоставлению с историей.
Добавляется только публичный логический ID события; UUID зон, координаты,
числа мобов, чат, имена, секреты и консоль не передаются модели.

Данные первого среза синтетические: собственный каталог15событий,
явно описанная эвристическая политика выбора/разнообразия и курированные
контрпримеры. Это имитация заданной политики, не доказательство обучения
на успехах настоящих игроков. Реальный decisions.sqlite3 читается только
для агрегированного аудита достаточности данных, без импорта сырых логов.

JSONL row: id, family, split, context, target={option:int},
acceptable_options:[int], provenance={kind:synthetic_policy,policy:...}.
Train/validation/test разделены по семействам исходных ситуаций до перестановок
и вариаций; нет общих id/context hashes, ответ всегда указывает допустимый индекс.
Одинаковый seed и каталог дают одинаковые байты. Перестановки не смешивают split.
Есть случаи без истории, повторного отражения атаки, смены стороны давления,
мягкого давления, всех сезонов/фаз, неизвестной прошлой записи и одного варианта.

## Обучение и оценка

Ревизия HF, базовый Docker digest, точные Python зависимости, seed, параметры
адаптера, hashes данных и отчёты сохраняются с запуском. Секретов/сетевых
учётных данных в контейнере нет; игровой мир не монтируется.
FP16 на Turing, batch1, короткий контекст и gradient checkpointing; сначала
ограниченная проба, потом конечный training run. Нет скрытого облачного обучения.

Основные метрики: согласие с допустимыми метками на held-out test, корректность
JSON/индекса, устойчивость к перестановке, повторы после отражения и задержка.
Исходная и обученная модель оцениваются на одинаковых входах/настройках.
Показатели слабого учителя называются policy agreement, а не игровым win rate.
Продвижение только при отсутствии нарушений контракта и регрессий критических
случаев, с выигрышем относительно исходной модели; иначе кандидат экспериментальный.
Training loss отдельно и не является критерием установки.

Экспорт адаптера обязателен. Слияние/конвертация в GGUF и проверка CPU/Ollama
делаются при пригодном кандидате; production model lock сохраняется до доказательств.
Весовые файлы/кеши/логи лежат в игнорируемом work, в Git — исходники/конфиг/сводки.
