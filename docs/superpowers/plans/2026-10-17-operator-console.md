# Operator console implementation plan

**Goal:** дать человеку живой журнал Minecraft и выполнение серверных команд из локальной админки.

**Architecture:** отдельный Python-модуль читает ограниченный хвост stdout/latest.log и отправляет команды через штатный RCON. Сервер остаётся привязан к 127.0.0.1; пароль читается только backend из server.properties. MCP и полномочия модели не меняются. HTTP-команды требуют same-origin, nonce и UUID квитанции; запись перед отправкой предотвращает повтор при сетевой ошибке. Неопределённый исход показывается явно, без повторной отправки.

**Tech stack:** Python stdlib, SQLite, Source RCON, существующие HTML/CSS/JS.

**Constraints:** не трогать игровой мир/моды; работающий сервер не перезапускать без согласования. Никакого Computer Use. Старые журналы могут содержать чат; консоль доступна только локальному оператору и не включается в экспорт ИИ.

- [x] RED: TCP fixture с фрагментированными/многочастными RCON-ответами, auth failure, потерей ответа; HTTP CSRF/validation/idempotency; bounded tail/rotation/secret redaction.
- [x] GREEN: admin_console.py, GET console/session + POST command, UI с журналом и историей ответов, подготовка RCON без перезапуска.
- [x] DOM-проверка вкладки, ошибок и однократной отправки; общий Python-набор и release check.
- [x] Ревью, локальный выпуск, обновление процесса админки без остановки Minecraft/ИИ.
- [x] Подготовить настройку RCON, согласовать единственный необходимый перезапуск Minecraft. После разрешения проверить реальную безвредную команду list, не изменяя мир.
