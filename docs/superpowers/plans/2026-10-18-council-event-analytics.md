# Два режима режиссёра и аналитика событий

Пользователь расширил текущий срез: режимы одной/двух моделей, подробная
аналитика отвлечения/обмана, урона и смертей. Исходное дообучение продолжается.
Исполнение автономное, отдельные коммиты, игровые проверки на накопленный срез.

## Контракт

- По умолчанию одна модель. Двойной режим явно включается конфигом; модели
  вызываются последовательно в одном CPU-контейнере с max_loaded_models1,
  mem_limit6GiB, ctx4096. Второй model digest фиксирован, не плавающий tag.
- Один раунд: предложение первой → критика второй → максимум один пересмотр,
  только при общем deadline. Ошибка критика сохраняет исходный выбор; итог
  остаётся разрешённым индексом. Никакой консоли/координат/численности модели.
- Фиксируются краткие структурированные результаты этапов/время/ошибки,
  а не скрытые рассуждения. Возврат/повтор неизвестного отправления сохраняет
  прежнее durable решение. Preview режим продолжает работать с одной моделью.
- Аналитика относится к operationId/eventId/zoneId и окну операции. Локальные
  ID игроков не попадают модели. Только подтверждённый фактический урон HP
  (1HP = половина сердца), отдельно поглощение/смерти и attributable source.
  Нельзя считать один удар/смерть у нескольких наложенных событий полностью.
- Отвлечение/обман — наблюдаемые proxy: реакция на предвестник, вход/выход
  радиуса, взаимодействие со следом, подход к ложному сигналу, вход в ловушку.
  Сохраняются raw counters, классификация и недостаточность данных. Одна
  близость к сигналу не доказывает услышанный звук или намерение игрока.
- Ограниченный журнал этапов/участников, сохранение на перезапуске; старые
  сценарии мигрируют с unknown/неполными данными. Повреждённые сохранения не
  сбрасываются. Новая статистика не загружает чанки и не сканирует мир.
- Коэффициенты очков и интервалы/пределы наблюдений задаются серверным config.
  История/карточка/агрегаты доступны в админке; вывод экранирован.

## Разделение работ

1. Python worker: council, config/load/runtime wiring, JSON guards, tests/docs.
2. Java worker: bounded persistent event analytics, adapters/hooks, tests and
   короткий GameTest с ускоренной логической шкалой; первым сообщить JSON contract.
3. Parent: реальный GPU run, замер второго CPU-моделя, админка аналитики,
   интеграция/общие проверки/отчёт/коммиты.
4. Независимый финальный review накопленного diff. Minecraft/world/profile
   не менять вживую; новый тестовый мир только после завершения тяжелого обучения.

## Review focus

Атрибуция/двойной счёт, отменённые damage/death, окно операции и рестарт,
bounded память/таймлайны, unknown вместо ложной уверенности, дедлайны моделей,
повтор прежнего pending решения, HTML injection, private данные в training.
