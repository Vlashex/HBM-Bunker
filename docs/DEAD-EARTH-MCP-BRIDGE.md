# DEAD EARTH — первый MCP-мост

Поверх [Expeditions](DEAD-EARTH-EXPEDITIONS.md) реализованы локальный Java-мост
и Python gateway с официальным MCP SDK 2.3.0. Это часть
[большого контракта](DEAD-EARTH-MCP.md): пока без нейросети, памяти SQLite,
биологических атак и климатических событий.

## Запуск и полномочия

Мост выключен по умолчанию. Только оператор с правом 2 может выполнить:

```text
/deadearth bridge start
/deadearth bridge status
/deadearth bridge stop
```

Start выбирает свободный порт на `127.0.0.1` и создаёт `dead_earth_bridge.json`
в корне текущего сохранения. Status сообщает путь и порт, но не секрет.
Дескриптор содержит 256-битный токен, UUID кампании и эпохи; не пересылай его,
не вставляй содержимое в чат и не добавляй в Git. При штатной остановке собственный
неизменённый дескриптор удаляется. Смена токена требует перезапуска gateway.

В архиве есть папка `director/`: свой Python-код, отдельный setup.ps1 и lock-файл
с хешами для Windows amd64 / Python 3.12. Настройка не меняет глобальный Python.
MCP host запускает `.venv/Scripts/python.exe -m dead_earth_director --bridge <путь>`
с рабочей папкой `director`. Код gateway не подключается автоматически к Codex
или другому приложению и не устанавливает языковую модель.

## Доступные инструменты

| Инструмент | Действие |
|---|---|
| get_snapshot | Снимок наблюдений и возраст кеша |
| get_history | Последние 1–100 событий |
| list_catalog | warning_beacon_v1 и relay_broadcast_v1 |
| preview_scenario | Проверка выбранного события без запуска |
| propose_scenario | Постановка выбора в очередь по request_id |
| get_scenario_status | Серверная квитанция по scenario_id |
| cancel_scenario | Отмена ожидающего сигнала с ожидаемой ревизией |

Каталог фиксирован: тестовый сигнал и [радиопередачи обнаруженных станций](DEAD-EARTH-RADIO.md).
У preview/propose есть необязательные каталог, цель, вариант и задержка;
без них сохраняется прежний сигнал. Нет консоли,
доступа к файлам, SQL, команд спавна, произвольных NBT и мощности взрыва.
Повтор request_id с прежним выбором возвращает прежний сценарий; другой выбор отклоняется. Отмена RPC не откатывает уже
принятый сценарий: после неизвестного исхода повтори тот же request_id.

## Технические границы

- MCP между host и Python работает через stdio; Python → Java — ограниченный
  локальный TCP-протокол, не открытый HTTP-сервис.
- Каждый запрос проверяет токен, кампанию и эпоху. Gateway не принимает внешние
  адреса и намеренно не подхватывает изменённый дескриптор во время работы.
- Вход до 8192 байт, вложенность до 16, ответ до 262144 байт. Полный ввод кадра
  ограничен двумя секундами; медленные фрагменты не продлевают окно. На отправку
  ответа тоже отведены две секунды: отдельный таймер закрывает зависшее соединение,
  чтобы единственный I/O-поток мог обслужить следующий запрос.
- Единственный I/O-поток работает с кешем и ограниченной очередью. До 32 запросов,
  не более двух обработок за серверный тик, не начатые запросы истекают через две секунды.
- Работа с миром и checkpoint выполняются только на главном серверном потоке.
  Снимок обновляется раз в 200 серверных тиков, даже при остановленных часах кампании.
- MCP-проекция содержит до 64 игроков, 128 последних регионов, 100 событий и 64
  известных объектов. Возвращается число пропущенных записей; полного знания карты нет.
- Сырые MCP-аргументы проверяются до преобразований SDK: опечатки и строка
  вместо числа не заменяются значениями по умолчанию.
- Ожидаемые ошибки возвращают безопасный код, например unauthorized, stale_context,
  request_expired или bridge_unavailable, без токена и внутреннего traceback.

Остановка Python/gateway не останавливает кампанию. Начатые сценарии продолжаются
по серверным правилам. Остановка моста отклоняет ещё не начатые запросы, но не
маскирует уже принятый сигнал как отменённый.

Источники SDK: [официальный репозиторий](https://github.com/modelcontextprotocol/python-sdk),
[зафиксированный выпуск](https://pypi.org/project/mcp/2.3.0/).
