# DEAD EARTH — Expeditions

Первый игровой объект и наблюдения поверх [Foundation](DEAD-EARTH-FOUNDATION.md).
Версия мода: `0.2.0-alpha.1`, Minecraft 1.21.1 / NeoForge 21.1.262 / Java 21.

## Наблюдения

Раз в 200 активных тиков координатор сохраняет последний известный регион 64×64,
измерение и здоровье онлайн-игрока. Смерть записывается после завершения обработки
события, если оно не отменено и игрок действительно умирает. Отдельно фиксируются открытия
регионов. Содержимое инвентарей, сундуков и всех блоков карты не исследуется.

История ограничена последними 512 событиями; не более 64 игроков и 1024 известных
регионов. После достижения лимита регионов прежние факты остаются, новые регионы
не добавляются. Это ограниченное знание команды, не полный журнал сервера.
UUID игроков и наблюдения хранятся только внутри сохранения мира.

Операторские команды:

```text
/deadearth snapshot
/deadearth history 20
```

Снимок содержит последние наблюдения, активные часы, UUID кампании/эпохи и только
уже обнаруженные объекты. Административный список объектов доступен отдельно.

## Заброшенная станция связи

`relay_v1` — небольшой открытый объект 9×6×9 из 99 ванильных блоков: потрескавшийся
каменный пол, остатки колонн, антенна и кафедра. Это первый технический объект,
а не готовая сюжетная лаборатория. Автоматическая генерация мира ещё не включена.

```text
/deadearth site preview <x> <y> <z>
/deadearth site place <request_uuid> <x> <y> <z>
/deadearth site list
```

Координаты — нижний северо-западный угол пола. Требуются Overworld, загруженные
чанки, свободный объём 9×6×9, твёрдая опора под четырьмя углами, отсутствие сущностей
в объёме и расстояние от игроков не менее 32 блоков до центра. Площадка не очищается:
даже блок внутри пустой части будущего объекта вызывает отказ. Preview не загружает чанки.

Одинаковый UUID запроса и координаты возвращают прежний результат. Другие координаты
с тем же UUID отклоняются. До установки блоков сохраняется `PLACING`, после — `READY`.
Прерванная установка становится `UNCERTAIN`; автоматического достраивания нет.
После загрузки сохранённый READY сначала получает `VERIFYING`. Проверка ожидает
естественной загрузки чанков: полный чертёж подтверждает READY, недостающие блоки
переводят объект в UNCERTAIN. Проверка выполняется также перед обнаружением.
Запись SavedData не объявляется атомарной транзакцией с сохранением блоков чанков.
Частичная постройка остаётся для проверки оператором. Лимит — 64 объекта на кампанию.

Живой игрок вне режима наблюдателя, приблизившись на 12 блоков к центру READY-объекта,
получает сообщение об обнаружении. В историю добавляется одна запись на команду.
Открытие пока не выдаёт предметы, EMC или исследовательские награды.

## Данные и совместимость

В папке данных мира добавляются `dead_earth_observations.dat` и `dead_earth_sites.dat`.
Оба файла привязаны к UUID кампании; неизвестная схема или повреждённый формат
сохраняются без замены и отключают координатор. Эти дополнительные данные не
запускают генерацию структур в существующих мирах.

В клиенте добавлена ранняя инициализация API ProjectE с загрузчиком его модуля,
до фонового построения подсказок. Внешний JAR, EMC и рецепты не меняются.
Полный результат проверки исправления фиксируется в отчёте выпуска.

Для разработки есть явный `-PdeadEarthClientSmoke` вместе с
`-PdeadEarthSmokeServer=127.0.0.1:25582`: отдельный тестовый клиент проверяет реальные
подсказки в фоне, делает снимок экрана и закрывается. Обычный профиль этот режим
не включает. Тесты не являются подтверждением нагрузки шести игроков.

Для независимого GameTest-прогона задавай новую папку, например
`runGameTestServer -PdeadEarthGameTestDirectory=run-gametest-expeditions-check2`.
SavedData в прежней папке сохраняются между запусками; повторный прогон с теми же
координатами не должен обходить защиту от наложения зарегистрированных объектов.

Следующий срез: локальный мост и MCP для чтения снимка, каталога и предложений
через существующую серверную очередь. Погодные циклы и автономный ИИ ещё впереди.
