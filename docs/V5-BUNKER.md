# Защита стартового бункера v5

Стартовый бункер OutpostZero защищается первые 180 минут **активной общей кампании**: 216000 тиков `Campaign.activeTicks`. Таймер начинается с нуля кампании. Выход всех игроков останавливает часы кампании; рестарт, новый участник, повторный вход и повторное обнаружение бункера срок не продлевают. Срок сохраняется в `data/dead_earth_safe_bunker.dat`; изменение длительности в конфиге не меняет уже сохранённый срок.

По умолчанию защищены исходные блоки конструкции и оборудование. Двери, люки и прочие изменения свойств того же блока продолжают работать; содержимое контейнеров можно брать и класть. Построенные игроками блоки в ранее свободных местах можно разбирать. Защита предотвращает замену исходного типа блока до изменения мира; восстановления разрушенного блока, повторного лута и выдачи копий нет.

В `config/dead-earth-server.toml`:

~~~toml
[starter.protection]
enabled = true
minutes = 180
preventAllBreakingInside = false
scanBlocksPerTick = 4096
~~~

`preventAllBreakingInside = true` запрещает разрушение любых непустых блоков внутри зафиксированных комнат и шахты, включая новые постройки. Изменения свойств дверей разрешены и в этом режиме. Отключение защиты не удаляет исходный снимок и не создаёт новый срок.

## Откуда берутся границы

Для новых миров scope Mixin охватывает фактический вызов `StarterBunkerLogic.placeStarterBunkerIfNeeded` с четырьмя аргументами. Это сохраняет идентичность стартового объекта даже при выборе другого content kind. Внутри scope записываются bounding boxes реально размещённых `StructureTemplate`; низкий перехват `LevelChunk.setBlockState` собирает последние типы исходных блоков, включая превращение marker в оборудование. Снимок завершается после нативной финализации. Открытие сундука, местоположение игрока и обычные дополнительные бункеры не создают защиту.

Границы комнат сохраняются отдельно: промежуток между модулями не становится большой безопасной прямоугольной зоной. Ограничения снимка: 192 области, 131072 исходных блока и 524288 суммарных блоков объёма. Неизвестная схема, повреждённый файл или превышение лимита сохраняются для диагностики; автоматической замены данных нет.

Для существующего мира без снимка используется read-only адаптер OutpostZero 1.0.20. Он читает известную схему `outpostzero_starter_bunker.dat`, проверяет `Origin*`, `BarracksSpawn` и `Spoke`, восстанавливает детерминированный план через чистые нативные helper-методы и сверяет его с реально загруженными шаблонными блоками. Кольца шахты проверяются по нативной сетке сегментов; верхний люк — во всём допустимом столбце той же шахты, с отдельной проверкой trapdoor. Каждый принятый сегмент требует физического совпадения шаблона. Чтение мира ограничено `scanBlocksPerTick`; отсутствующие чанки ожидаются, без force-load.

Адаптер не вызывает родной `computeIfAbsent`, генерацию или размещение. При неизвестных полях, изменившемся плане, повреждённом сохранении или недостаточном физическом совпадении миграция прекращается с записью в журнал. До окончания проверки старого мира защита ещё не активна. Родной файл не изменяется.

Старый мир не хранит полную историю редактирования блоков: миграция защищает сохранившиеся совпадающие шаблонные блоки и распознанные marker-устройства. Замена игроком на идентичный исходному тип исторически неотличима; отсутствующие и заменённые на другой тип блоки не восстанавливаются. Новое нативное размещение получает полный снимок.

## Препятствие для монстров

Проверяются `Monster`, категория `MobCategory.MONSTER` и тег `mutationcraft:mutants`. Игроки, обычные животные и приручённые `TamableAnimal` не блокируются. Запрещены spawn/join внутрь области и перемещение/телепорт через неё: проверяется весь swept AABB/segment, а не только конечная точка. Уже загруженные враждебные существа внутри ограниченно удаляются без смерти и дропа; им разрешено выходить наружу. Урон по находящемуся внутри существу от распознанного враждебного атакующего также отменяется.

Флаг активности, текущее активное время и режим полного запрета публикуются из server tick через volatile-поля. Worker HBM использует только опубликованный флаг и неизменяемые списки/карты; живой CampaignStore и блоки мира из worker-hook не читаются.

## Пути разрушения и проверки

Основной слой покрывает BreakEvent, список блоков ExplosionEvent, поршни, `Level.setBlock`, `Level.destroyBlock` и прямой `LevelChunk.setBlockState`. Нативные `Block.dropResources` подавляются для защищённого блока до попытки удаления. Отдельный адаптер HBM beta.10 фильтрует `ChunkUtil.carveLocal` и `applyToSnapshot`: защищённые блоки исключаются до записи в section snapshot и журнал разрушения. Незащищённые соседние блоки взрыв продолжает разрушать. Исходная нативная маска не изменяется; worker использует опубликованный снимок защиты.

JUnit `SafeBunkerStoreTest` проверяет границу 215999/216000, сохранение срока, принадлежность кампании, сохранение неизвестной схемы, различие исходных/игроковских блоков и проход через весь объём одним перемещением. Значение активного времени подставляется напрямую: ожидания трёх часов нет.

GameTest namespace `dead_earth_starter`, batch `safe_bunker`: физические setters/destroy/drops, двери и контейнеры, новые блоки игрока, hostile join/move/teleport, пассивное животное; отдельный тест вызывает настоящий pinned OutpostZero placer внутри capture scope и проверяет оборудование, модули, шахту и чтение сохранённого снимка новым DimensionDataStorage. Batch `safe_bunker_migration` размещает настоящий native-бункер без capture, получает его настоящие нативные SavedData-поля в памяти и проверяет восстановление через тот же read-only адаптер; исходный нативный файл не перезаписывается.

Общий прогон v5 подтвердил эти проверки с полным серверным составом. Тест реального HBM raw-carving сначала воспроизвёл обход обычной защиты, затем прошёл с адаптером; проверены и защищённый блок, и разрушение соседа, и отсутствие защищённого блока в destruction/drop ledger. Это проверка закреплённой версии HBM; неизвестные будущие способы прямого изменения palette требуют отдельной проверки. Работающий сервер и пользовательские миры разработкой не заменяются.
