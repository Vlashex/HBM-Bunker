# Локальное дообучение выбора тактик

После первого обучения выполнено [ручное A/B/C-сравнение промптов](DEAD-EARTH-PROMPT-AB.md):
88 полных ответов основной модели, кандидата и критика, слепые оценки до раскрытия
подписей. Рабочие веса/промпты сохранены; новый подробный промпт сам по себе
не улучшил проверенный CPU-срез. Эти уже просмотренные ситуации нельзя выдавать
за независимый test следующей итерации.

Отдельный эксперимент, не часть запуска игрового сервера. Модель возвращает
только `{"option":N}` из вариантов, уже допущенных сервером. Игровые миры,
консоль, чат и секреты в контейнер не монтируются. Рабочий CPU model pin
не меняется командами обучения.

## Данные

Из каталога создаётся синтетический curriculum с явно заданной слабой
политикой: история отражённых атак, смена стороны давления, сезон и вес.
Это имитация желаемых предпочтений, не обучение на успехах настоящих игроков.
Семейства ситуаций разделяются до вариаций/перестановок; provenance и хеши
сохраняются в manifest. Существующий набор не перезаписывается.

Из `director/`:

```powershell
.\.venv\Scripts\python.exe -m training.dataset --catalog ../pack/config/dead-earth/director/catalog.json --out ../work/director-training/NEW/data --seed 20261018
```

## Контейнер

`Dockerfile` рассчитан на CUDA, Turing SM75+, FP16, QLoRA NF4. Сначала
проверь один настоящий optimizer update (`--probe`), затем отдельный конечный
run. GPU используется при обучении; рабочий режиссёр остаётся на CPU.
На ПК с 32 ГБ обучение проводят отдельно от одновременной игры клиента/сервера.

Нужны PyTorch/Transformers/PEFT и официальный NVIDIA Container Toolkit в
Docker-среде. Его установка и перезапуск Docker — отдельная настройка среды;
этот модуль её не выполняет. Windows Docker CLI и Ubuntu Docker могут указывать
на разные daemon: выбери тот, для которого проверено `--gpus all`.

Конфиг JSON требует `model_id`, точный `model_revision` (40 hex), `base_commit`
(проверенный commit исходников). Не используй плавающий `main`. Необязательный
абсолютный `model_path` разрешён только с `base-pin.json`:

```json
{"model_id":"Qwen/Qwen3.5-4B","model_revision":"851bf6e806efd8d0a36b00ddf55e13ccb7b8cd0a","files":{"config.json":"SHA256","model.safetensors":"SHA256"}}
```

В реальном manifest перечисляются все файлы весов, tokenizer/config/template
с их настоящими SHA256. Проверяется покрытие и каждый хеш; пример выше
показывает формат и сам по себе не является допустимой квитанцией.

Запуск внутри контейнера с исходниками `director/` в `/app`, данными и новым
выходным каталогом в `/run`, локальными весами `/cache/base4b`:

```text
python -m training.train --config /run/config.json --data /run/data --output /run/probe-1 --probe
python -m training.train --config /run/config.json --data /run/data --output /run/train-1
```

Для загруженных заранее весов: `--network none`, `HF_HUB_OFFLINE=1`,
`TRANSFORMERS_OFFLINE=1`; исходники и кеш монтируются read-only. Приватные
runtime каталоги режиссёра не монтируются. Выходной каталог обязан быть новым;
OOM/ошибка сохраняются в отчёт, скрытого CPU offload нет.

Пределы: batch1, контекст до1536, LoRA rank8/alpha16, максимум64 updates.
Loss только по JSON-ответу и EOS; suffix logits исключают огромный полный
vocabulary tensor. Замороженные embeddings/head остаются FP16, нормы FP32.

## Оценка и артефакты

`run.json` содержит ревизии/хеши данных и исходников, версии библиотек,
число реальных optimizer updates, память, время, baseline/after. Адаптер и
tokenizer сохраняются с хешами; логи/веса остаются в игнорируемом `work/`.

`constrained_logit_choice` сравнивает только допустимые индексы и **не измеряет
корректность JSON**. Отдельные полные greedy generations проверяются строгим
runtime parser. Agreement считается по всем строкам, ошибки включаются в
знаменатель. Смотри также семейства, повторы после отражения и устойчивость к
перестановкам; при малой подвыборке группы могут быть неполными. Для первого
среза используй `test_rows=160`, чтобы покрыть весь held-out test.

Чекпоинт нельзя выбирать по test. Снижение training loss не означает улучшение
игрового опыта. Пригодность CPU/GGUF кандидата проверяется отдельно; рабочий
`models.lock.json` не заменяется автоматически.

Текущая синтетика использует уникальные event ID в одном списке вариантов.
Runtime также допускает одинаковое событие для разных зон: такие случаи
потребуют расширения curriculum перед обучением на реальных решениях.
