# DEAD EARTH — архитектура ИИ-режиссёра

Дата: 17 октября 2026. Статус: план следующего среза после локального v3.0.0.
Этот документ уточняет пользовательский черновик; реализация нейросетевого цикла
и Docker-запуск пока не выполнены. При расхождении с ранним
[проектом MCP](DEAD-EARTH-MCP.md) для режиссёра используется этот документ.

## Основа и границы

Код сервера определяет цель, бюджет, допустимые места появления, состав и число
противников, предупреждения, сроки и передышки. Модель выбирает оформление
из разрешённых вариантов и пишет короткие тексты. Сценарии работают и без модели:
таймаут, отказ или неверный JSON приводят к проверенному варианту из каталога.

Уже реализованы часы кампании, сохранение сценариев, наблюдения, ограниченный
MCP-мост, радиосценарии, сезоны, адаптивная биосфера и оценка зон.
Это не означает, что уже готовы выбор атак, команды отрядам или ИИ.
В сборке установлен Mutationcraft Legacy, а не оригинальный Scape and Run.
Его адаптацию и доступные формы нельзя выводить из описания SRP.

Зоны остаются областями вокруг нашего блока zone_loader. Пересечения объединяются
по существующим правилам. Статические маркеры дополняют зону ролями подходов
approach/flank/rear/distraction и особыми объектами, но не заменяют её границы.
При объединении или разделении зон прежняя цель может исчезнуть:
ожидающий сценарий должен пройти повторную проверку, а не переноситься молча.

Текущая оценка: EMC ресурсов × коэффициент − ранги оснащённых турелей
+ ранги пустых турелей. UNKNOWN не означает отсутствие обороны.
MCP сейчас передаёт компактные итоги зон. Отдельный ограниченный запрос подробностей
целей и подходов ещё предстоит добавить; топливо генераторов, питание дверей,
маршруты и покрытие огнём пока не являются готовыми наблюдениями.

## Что меняется в черновике

| Предложение | Принятое направление |
|---|---|
| Компенсировать всех убитых на подходе | Конечный бюджет всей операции, включая подкрепления. Эффективная оборона действительно снижает давление. Данные о потерях уточняют следующие атаки, не создают бесконечный досыл |
| Всегда находить обход SecurityCraft | Только проверенный доступный подход. Если его нет — другая тактика, пауза или отказ; телепортации через защиту нет |
| Модель создаёт произвольную цепочку шагов | Сначала готовый серверный граф и несколько вариантов подачи. Ограниченное связывание шагов добавляется после рабочего исполнителя |
| Сразу 15 тактик с вариациями | Одна законченная операция, затем три различающиеся тактики; расширение по результатам игры |
| Полный снимок на 300–600 токенов | Краткий дайджест выбранных целей и исходов. Его объём измеряется; полное состояние в запрос не помещается |
| Враг сам приобретает нужную адаптацию | Только подтверждённые механики установленных модов; новые поведения требуют собственных адаптеров |
| Разбитые турели как следы | Улики в допустимых местах. Игрокам не ломают исправную оборону ради постановки |
| Неоконченный сценарий ждёт бесконечно | Ограниченная пауза с причиной, сроком, квотой и явным исходом |
| Облачный анализ обязателен | Локальная база полностью самостоятельна; облако — отдельное последующее расширение |

Модель не обязана оценивать уровень угрозы или выбирать тактику по сырым логам.
Журнал исходов сначала изменяет веса тактик в коде. Модель использует тот же
проверенный итог, чтобы оформить событие и связать его с прошлым.

## Распределение ответственности

1. Java: наблюдения с возрастом и полнотой, расчёт целей и бюджета, разрешённые
   варианты, все проверки, часы, исполнение, квитанции и исходы.
2. Python host: расписание запросов модели, компактный дайджест, строгий разбор
   ответа, обращение к существующему ограниченному мосту и журнал решений.
3. Локальная модель: идентификатор варианта подачи и короткий текст из разрешённой
   формы ответа. Позднее — выбор разрешённой роли подхода и ограниченные ветвления.
4. MCP: операторский пульт к тем же серверным операциям. Универсальная консоль,
   произвольные координаты, NBT, команды и файловые пути модели не выдаются.

Первый контракт ответа модели содержит только разрешённый идентификатор варианта
и короткий текст. Нет координат, численности, характеристик мобов, команд
или абсолютного времени запуска. Дополнительные поля, дубли ключей, неверные типы,
неизвестные ID, чрезмерный размер и NaN/Infinity отклоняются.
JSON Schema ограничивает генерацию; независимая проверка всё равно обязательна.

Модель не получает токен моста. В её контейнер не монтируется игровой мир.
Чат игроков не нужен первому срезу. Если он появится позднее, это недоверенные
данные, которые не меняют инструкции и полномочия.

## Локальная модель и Docker

Основной выбор: Qwen3.5-4B в квантовании Q4_K_M, Ollama в Docker.
На проверенном ПК NVIDIA GeForce RTX 2060 SUPER с 8192 MiB VRAM.
Официальный пакет qwen3.5:4b содержит квантованные веса примерно 3.3 GB;
в полном варианте также есть дополнительные файлы. Память контекста,
среда выполнения и Minecraft требуют дополнительного места.
Это основание выбора, а не подтверждённая оценка скорости совместной работы.

Стартовый профиль: контекст 4096, ответ до 512 токенов, один запрос одновременно,
отключённое рассуждение, ограниченный таймаут и выгрузка модели после запроса.
Поддержку отключения рассуждения проверяем через API конкретной закреплённой версии.
Перед первым рабочим запуском закрепляем версию образа, digest и ревизию модели;
latest и незаметное обновление модели не используются.

В Docker работает модель; лёгкий Python host и Minecraft первоначально работают
в Windows. Так сохраняется существующий мост на 127.0.0.1 без публикации игрового
управления в сеть. Порт Ollama также публикуется только на 127.0.0.1.
Не требуется переносить сервер Minecraft в контейнер или добавлять Web UI,
векторную БД и дополнительный агентский фреймворк.

Docker CLI и Docker Desktop по стандартным путям пока не обнаружены.
Проверка WSL ограничена правами текущего процесса; его готовность не подтверждена.
Для NVIDIA в Linux-контейнере Docker Desktop использует WSL 2.
Установка и проверка этого основания предшествуют заявлению о Docker-запуске.
Перезагрузка Windows, если потребуется, оформляется отдельно, без внезапного
прерывания текущей работы пользователя.

Источники, проверенные 17 октября 2026:
[модель и квантование](https://ollama.com/library/qwen3.5:4b),
[карточка Qwen](https://huggingface.co/Qwen/Qwen3.5-4B),
[Ollama Docker](https://docs.ollama.com/docker),
[JSON Schema](https://docs.ollama.com/capabilities/structured-outputs),

## Наблюдения и выбор цели

Сбор наблюдений — ограниченные проходы раз в 30–60 секунд, без принудительной
загрузки мира. Модель вызывается ориентировочно раз в 15 минут активной кампании,
либо по существенному событию с общим ограничением частоты.
Отсутствие игроков или перегрузка сервера откладывает новые решения.

Сервер сначала фильтрует допустимые цели по возрасту, полноте, измерению, наличию
подхода, защите после смерти, повторяемости и действующим операциям.
Затем рассчитывает приоритет: базовая ценность зоны и явные коэффициенты
давности, расстояния и обнаруженных обстоятельств. Бюджет атаки считается отдельно:
высокий приоритет не означает разрешение на неограниченную волну.

Дайджест включает несколько лучших кандидатов, выбранную цель и её ограничения,
сезон, текущую сложность и ограниченную сводку исходов. Для первого профиля целимся
примерно в 2000 входных токенов вместе с инструкцией и схемой, с запасом внутри
контекста 4096. Предел проверяем замером, не подсчётом символов «на глаз».

Уже действующие сезонные и адаптивные коэффициенты HP/урона учитываются при
выборе бюджета. Режиссёр не накладывает их повторно на тех же мобов. Собственные
подкрепления ограничены также нагрузкой и наблюдаемой популяцией вокруг цели.

## Жизненный цикл и честность

Расширение опирается на существующий Scenario Engine. Предложение, проверка,
резервирование бюджета, предупреждение, исполнение, пауза и завершение имеют
явные переходы. Считаются и активные, и приостановленные операции: не более трёх
занятых слотов, плюс ограниченный срок паузы и очередь. Сильная связка — одна
на цикл давления; передышки и повторы ограничиваются глобально и по цели.

Сроки используют активные часы кампании, не ожидание реальных суток.
Перед каждым воздействием повторно проверяются цель, загруженность, условия
и неизрасходованный бюджет. Нет спавна перед игроком или в недоступных чанках,
нет бесконечных попыток найти путь и индивидуального глобального pathfinding.

Запрос связан с campaign_id, world_epoch, целью, версией политики и сроком действия.
Запоздавший ответ модели не исполняется. Повтор запроса сохраняет request_id
и не создаёт новую волну. После сбоя RUNNING не превращается в повтор эффекта:
нужны квитанция и сверка результата, иначе остановка с неопределённым исходом.

Игровые лимиты, коэффициенты, бюджеты, паузы и частота решений принадлежат
серверному конфигу. Настройки модели, адрес и технический таймаут — конфигу host.
Модель не может менять политику через собственный JSON.

## Порядок внедрения

| Срез | Что делаем | Признак готовности |
|---|---|---|
| D1 — рабочая база | Docker/Ollama, host, ограниченный снимок, одна цель, схема ответа, запасной вариант, журнал, серверный preview | Реальная локальная генерация и проверка предложения в отдельном мире; при недоступной модели цикл продолжает работать. На этом этапе мир не атакуется |
| D2 — одна операция | Конечная разведывательная атака Mutationcraft: подход, предупреждение, бюджет, исход, квитанции | Операция реально проходит от выбора цели до исхода; турели могут полностью отбить её, рестарт не дублирует волну |
| D3 — лес и выбор тактик | Одно подтверждённое воздействие Overgrown, три тактики, общие лимиты, передышки, пауза/возобновление | Паразиты и лес используют единые правила давления; нельзя обойти лимиты параллельными сценариями |
| D4 — память и расширение | Исходы меняют веса, история повторов, буфер загадок, новые шаблоны по мере необходимости | Серия операций меняется по реальным результатам, не по выдуманному отчёту модели |
| D5 — постановка | Звуки, следы, клиентские эффекты, фактические досье; при необходимости отдельные адаптеры света/камер | Эффекты связаны с реальным событием, защиты и производительность сохранены |

Досье разделяет проверенные факты и художественное оформление. Сведения о
существовавших объектах, жертвах и исходах берутся из журнала. «Предсказание»,
которое запускается чтением, позднее становится явным игровым триггером с
повторной проверкой ограничений, а не доказательством предвидения модели.

Ядерные события HBM, метеориты, сложные отряды, помехи камер и облачная ревизия
не входят в рабочую базу. Они добавляются после законченных D1–D3 отдельными
проверяемыми примитивами. Сначала работающий цикл, затем ширина каталога.

## Проверки без долгих ожиданий

Часы, передышки, квоты, старение снимков, паузы, выбор цели и серии исходов
проверяем управляемым временем. Контракт модели — заранее заданными корректными,
повреждёнными и запоздавшими ответами; отказ не должен нарушать серверный цикл.
Сохранение и сбой проверяем между шагами, включая неопределённый исход воздействия.

Полный запуск клиента и сервера — на связный срез. В отдельном тестовом мире
проверяем короткую операцию и сохранение/перезапуск. Отдельно измеряем совместную
работу Minecraft и модели: задержку тиков, загрузку памяти и время генерации.
Короткий тест не объявляется проверкой кооператива на шесть игроков.
