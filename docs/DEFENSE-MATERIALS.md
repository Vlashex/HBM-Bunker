# Стены, двери и люки V1–V3

Защитный срез 5.3.0 / coordinator 4.2.0. Нагрузочные измерения сборки 5.2.0
проводились без этого кода; они не подтверждают его стоимость в большой осаде.

| Класс | Прочность по умолчанию | Оформление | Рецепт одной стены |
|---|---:|---|---|
| V1 | 1000 | Сталь текущего бункера Outpost Zero | Железный блок + Reinforcer SecurityCraft |
| V2 | 2000 | Более тёмная сталь | V1 + 2 пластины стали HBM |
| V3 | 8000 | Самая тёмная сталь | V2 + 2 титановые пластины + 2 пластины Dura Steel HBM |

Из шести стен одного класса получается одна дверь, из четырёх — один люк.
Стены, двери и люки имеют отдельные ID `dead_earth:defense_{wall,door,hatch}_v{1,2,3}`.
Прочность двери общая для обеих половин. Открывание, закрывание и редстоун
не восстанавливают HP. Повреждённые позиции сохраняются на диске; каждый блок
не создаёт собственную block entity и не требует отдельного тика.

## Крафт и автоматизация

Reinforcer находится в сетке вместе с исходным блоком и возвращается как
crafting remainder. Lvl1/lvl2 расходуют одно использование, последнее ломает
инструмент. Имена и остальные компоненты сохраняются. Нативный lvl3 не
изнашивается и подходит для повторяемого шаблона автокрафта. Износ lvl1/lvl2
меняет точный ключ предмета в AE2; один exact pattern не может бесконечно
использовать такой изменяющийся ключ.

Для RFTools Crafter режим EXTC оставляет остаток инструмента во внутреннем
инвентаре. KEEP требует запас больше одного, поэтому не подходит единственному
Reinforcer. По закреплённому коду RFTools 7.0.12 `CrafterBaseTE.craftOneItem`
вызывает recipe-level `getRemainingItems`, а при нехватке места откатывает
операцию. Это проверка кода; работающая машина RFTools и её GUI не тестировались.
Для AE2 нативный тест проверяет encode/decode pattern и возврат инструмента,
но не пользовательский запрос к большой ME-фабрике.

Готовые защитные изделия имеют EMC=0. Улучшения сохраняют роль металлургии HBM;
новые рецепты не дают дешёвых стали или пластин.

## Как расходуется прочность

Настройки находятся в `config/dead-earth-defense.toml` на сервере:

| Источник | Урон по умолчанию |
|---|---:|
| Удар копателя ImprovedMobs | 50 раз в 20 тиков |
| Попытка туннелирования Arbora | 100 |
| Отдельное разрушение кратером Siege | 250 |
| Другой LivingEntity через поддержанный destroy-путь | 50 |
| Обычный взрыв / HBM VNT | 100 × мощность взрыва |

V3 блокирует заражение Putrid/Hook, конверсию леса и прямую замену через
поддержанные setters. Атаки известных копателей и взрывные адаптеры расходуют
HP до разрушения. Это не общая реализация HP-урона для каждого оружия: отдельные
пули и неизвестные сторонние raw writers требуют своих адаптеров.

Ядерный иммунитет не добавляется. У материалов конечное взрывное сопротивление;
поддержанные ядерные writers HBM сохраняют нативное разрушение. Обычная разборка
игроком и команды оператора разрешены. Поршни не перемещают эти блоки, чтобы
не отделять повреждённый материал от его сохранённой позиции.

В первые три часа кампании защита исходного стартового бункера имеет приоритет:
удары не снимают скрытые HP под временным щитом. Миграция не продлевает этот срок.

## Старые миры и генерация

Пользователь подтвердил исходный материал `outpostzero:steel_block`. Только он
сопоставляется с V1 по умолчанию. Его старый registry ID сохраняется для чтения
сохранений; рецепт и отображение старого изделия убираются из обычного получения.
Новые шаблоны получают V1 при чтении палитры. Другие материалы SecurityCraft
сохраняются.

Миграция посещает только уже загруженные чанки. Проверка палитр отсекает чанки
без исходного материала; сканирование и очередь имеют настраиваемые бюджеты.
До замены пишется журнал исходного состояния. Контейнеры, неизвестные block
entity и несовместимые свойства пропускаются. При нечитаемой схеме или ошибке
журнала замены прекращаются с сохранением исходных файлов.

Синхронный checkpoint полного журнала остаётся разовой стоимостью миграции и
растёт с числом перенесённых блоков. Мобы только запрашивают очередь: внутри
их AI-тика журнал не переписывается. Эта стоимость не измерена в нагрузочном
отчёте исходной сборки 5.2.0.

Внешний вид стены V1 ссылается на текстуру установленного Outpost Zero.
Исходные текстуры дверей/люков SecurityCraft используются по MIT; лицензия и
атрибуция включены в assets собственного мода.
