# Аналитика операций режиссёра

Измерения привязаны к `operationId`, `eventId`, `zoneId` и времени кампании.
Они не являются оценкой намерений игрока, успеха сценария или ресурсных потерь.
Игровой `outcome` хранится отдельно от наблюдаемых прокси.

`dead_earth_event_analytics.dat` — отдельный ограниченный SavedData. Неизвестная
схема, чужая кампания, недопустимые поля/границы и повреждённый файл отключают
аналитику, сохраняя исходные данные. Кампания и игровой режиссёр продолжают
работать. Старые операции получают `coverage: unknown`; восстановленные активные
операции — `partial`, поскольку непрерывного наблюдения через перезапуск нет.

## Подтверждённый ущерб

`LivingDamageEvent.Pre/Post` сопоставляются по игроку, источнику и серверному
тику. Учитывается фактически потерянное здоровье, ограниченное итоговой величиной
урона после модификаторов. Overkill не увеличивает потерю выше здоровья до удара.
Поглощение — отдельное фактическое уменьшение absorption, ограниченное нативным
reduction ABSORPTION. Один HP соответствует половине сердца. Один только входящий
amount, отменённый/неуязвимый удар или искусственная публикация Post не создают
измерение урона.

Смерть подтверждается после завершения dispatch: событие не отменено, игрок
мёртв и нативный счётчик `Stats.DEATHS` увеличился. Повтор одного подтверждения
за жизнь не создаёт новую смерть. UUID игроков используются только в backend
и сохранении; публичные DTO содержат количество участников и признак усечения.

Один удар/смерть относится максимум к одной операции. Метка владельца
атакующего, включая владельца снаряда, имеет приоритет в активном окне операции.
Просроченная owned-метка не переносит ущерб на соседнее событие. Без owned-метки
выбирается ближайший центр подходящей активной операции в том же измерении и
радиусе, затем время создания и UUID разрешают равенство. Это
`spatial_association`, а не доказанная причинность.

`damage.points = hp × hpWeight + deaths × deathWeight + absorbedHp × absorbedWeight`.
По умолчанию веса 1/20/0. Веса замораживаются при создании записи операции и
сохраняются в `damage.pointsWeights`; текущие настройки находятся в
`analytics.scoring`. Изменение конфига не пересчитывает историю другими весами.

## Наблюдаемые действия и движение

Таймлайн отражает только фактическое выполнение: звук после окончательного
неотменённого PlayLevelSoundEvent (ненулевой sound/volume), подтверждённую
установку следа, доставку частиц, успешный `addFreshEntity` или принятую команду
навигации. Принятая навигация не доказывает найденный путь или перемещение моба.
Null level/anchor, лимит следов, отказ spawn/navigation не создают успешное
действие. Разрушение следа подтверждается после BreakEvent и изменения блока;
вода/огонь — после успешного удаления следа. Inspect — фактический вызов
взаимодействия блока после нативных guards.

Отслеживаются переходы относительно реально созданных cue anchors: первое
наблюдение — только baseline; уменьшение дистанции на `approachDelta`, вход
в `nearRadius`, выход за `nearRadius + approachDelta`. Пара наблюдений должна
уложиться в два интервала sampling, а cue — в reaction window. Участники вне
радиуса операции или другого измерения не опрашиваются. Используются только
живые online игроки, время — `Campaign.activeTicks`; без игроков шкала стоит.
Чанки не запрашиваются, мир и сущности ради аналитики не сканируются.

`trapEntries` — наблюдаемый вход в радиус места реально созданной волны у тактик
lure/feint/fork/excavation_trap/seasonal_ambush/pursuit_trap. Это прокси входа в
опасную область, а не вывод об обмане или мотивации. Счётчики относятся к cue
anchors, поэтому разные cues могут зафиксировать одну траекторию несколько раз.
`samplePairs` показывает объём парных наблюдений.

Классификации `observed`, `not_observed`, `insufficient_data` консервативны:
подход/взаимодействие даёт observed для distraction proxy; вход в trap anchor —
для deception proxy. Отсутствие реакции выводится только после завершения при
полном покрытии и парных наблюдениях. Одна близость, пустой журнал или пропуск
наблюдений не доказывают услышанный звук, отвлечение, обман или отсутствие реакции.
Отдельный `proxy.score` — взвешенная сумма подходов/взаимодействий/trap entries,
не автоматическая награда модели.

## Лимиты и read-only JSON

Серверный `dead-earth-server.toml`, секция `director.analytics`:

| Настройка | По умолчанию |
| --- | --- |
| enabled | true |
| maximumOperations / maximumTimeline / maximumParticipants | 32 / 48 / 32 |
| sampleTicks / reactionWindowTicks | 20 / 600 |
| attributionRadius / nearRadius / approachDelta | 96 / 6 / 4 |
| hpWeight / deathWeight / absorbedWeight | 1 / 20 / 0 |
| approachWeight / interactionWeight / trapWeight | 1 / 2 / 3 |

Hard bounds: 128 операций, 128 строк на операцию, 64 идентификатора участников,
16 cue anchors. Reaction window фактически не меньше sampleTicks. При достижении
лимита участников coverage становится partial. Старые завершённые операции
вытесняются раньше активных. `totals` относится ко всем удерживаемым операциям,
а не ко всей истории кампании.

Хранилище аналитики использует схему2 с UTF-8 JSON в NBT byte array до8MiB;
схема1 с короткой строкой читается при миграции. Очередь сценариев и реестр
волн также переведены на byte array, с прежним лимитом1MiB каждого JSON.
Это устраняет ограничение NBT writeUTF65535байт. Неизвестные/повреждённые
файлы сохраняются без сброса. Перед откатом на старый координатор нужна
резервная копия мира: старые версии не читают схему2.

`snapshot.analytics` и `status.analytics` содержат schema/status/sampleTicks,
maxOperations/scoring, operations и totals. Операция содержит идентификаторы,
createdTick/expiresTick/endedTick, state/coverage, participants и
participantsTruncated, damage, observations, proxy, timeline, droppedTimeline.
Gson может опустить `endedTick` до завершения.

Summary передаёт максимум 16 последних операций и 16 последних строк на каждую;
дополнительный бюджет 80 KiB уменьшается остатком общего bridge frame. Счётчики
и totals не пересчитываются по этому срезу. `omittedOperations`, `omittedTimeline`
и `wireTruncated` показывают транспортное усечение. `droppedTimeline` означает
реально вытесненные строки ограниченного серверного журнала. У строк есть
монотонный `seq`, сохраняемый при перезапуске, для безопасного объединения срезов.

Read-only bridge operation `get_event_analytics` принимает только
`{operation_id: canonicalUUID}`. Ответ: `{schema:1,status,operation:row|null}`;
status — ready/not_found/unsupported_save/unavailable. Бюджет досье 60 KiB,
при необходимости строки также усекаются явно. Общий `MAX_OUTPUT` остаётся
262144 байта. Ни координаты, ни UUID игроков, ни консоль в этот DTO не входят.
Новый bridge read не добавляет модели командных полномочий.

Unit-проверки: EventAnalyticsTest, EventAnalyticsStoreTest, AnalyticsTransportTest,
BridgeProtocolTest. Нативные проверки EventAnalyticsGameTests находятся в уже
существующем namespace `dead_earth_cinematic_review`; отдельный живой сервер не нужен.
